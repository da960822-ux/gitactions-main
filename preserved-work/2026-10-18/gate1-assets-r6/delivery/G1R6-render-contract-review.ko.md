# Gate 1 R6 — 렌더 계약 수정과 공간 폴리시

R6 검증 기준 커밋: `491b16883d9ca1591065a22b23731f04587e5b38` (로컬만 저장, 푸시·배포 없음). 자산 버전: `chamber-v6.1`. 원본 source SHA-256: `8f0d5245c87da13497d0fb56f5930e1f25966ed88d788d4cac4c1faadbf0d5d9`. 전체 해시·재질 계약은 `render-version.json`과 `asset-manifest.json`에 기록했습니다.

Gate 1 정적 구도 검수용 자료입니다. 자체 합격이나 Gate 2 진입을 선언하지 않습니다. 승인된 캐리커처 원본, 모든 게임·API·라우트·한국어/스페인어·갤러리·편지·건의사항은 보호합니다. 패키지 변경·푸시·배포는 하지 않았습니다.

## 이번 수정

- 큰 원형 니치와 폐곡선 금속 테두리를 새 Hero의 중심에서 제거했습니다. 인물 뒤의 비대칭 석고 곡면은 바닥·후경으로 이어지고, 실제 glTF 모프를 통해 뒤로 펼쳐집니다.
- 인물 아래를 바닥에 잠기는 둥근 전경으로 재설계했습니다. 노출된 직육면체 끝단은 줄였으나, 아래쪽에 겹쳐 보이는 면이 여전히 받침이나 카운터처럼 읽히는지는 정적 구도 검수에 남깁니다.
- 왼쪽 문구 영역에서 커튼과 가구를 제거하고, 깊은 버건디 곡면과 오른쪽의 따뜻한 인물 강조광을 연결했습니다. 문구 원문은 바꾸지 않았습니다.
- 도착 공간에는 서로 다른 깊이의 두 곡면과 따뜻한/차가운 광선을 만들었습니다. 앞에서 보인 동일한 벽·전경·천장 메시가 실제로 변형되며 이 공간의 구조를 엽니다. 의자로 채운 빈 정면 방을 사용하지 않습니다.

## 렌더링 계약

| 항목 | R5에서 확인한 문제 | R6 처리 |
|---|---|---|
| 확산광 단위 | 단위 albedo당 출사 diffuse bake를 Three irradiance로 그대로 입력 | 저장 배율 1과 π 단위 변환을 별도 메타데이터로 기록. Half-float EXR 사용 |
| 직접광 중복 | DIRECT+INDIRECT 베이크 위에 새 직접광/RoomEnvironment diffuse 추가 | 런타임 diffuse 광원 없음. IBL diffuse도 셰이더에서 제외 |
| 반사 환경 | 원본과 무관한 RoomEnvironment | 같은 모델·발광 면·World로 중앙 Hero/도착 HDR과 wine 수신자 로컬 HDR 제작. specular에만 사용 |
| 환경 방향 | 좌표계 방향을 추측할 가능성 | 축 색상 실험으로 +X/+Z/+Y 방향을 측정하고 파노라마 열을 재배치 |
| 공유 재질 | 별도 광선 메시가 room atlas 상속 | 수신자별 원본 재질과 로딩 후 primitive 재질 분리. atlas 없는 광선에는 lightMap 미할당 |

| 노멀 Y | tangent 없는 glTF의 derivative 규약 누락 가능성 | glTFLoader 규약대로 tangent 미포함 시 normalScale.y=-1 |
| UV | UV2 부재를 근거 없이 문제로 판단할 위험 | 검증된 UV0 유지. UV1 재작업 없음 |

| 톤 매핑 | 원본 AgX / 웹 ACES를 일치로 오인 | 최종 AgX와 진단 Standard/NoToneMapping 캡처 구분 |
| 바닥 반사 | 투명 반사 화면을 바닥 위에 덧씌움 | 실제 반사 카메라의 선형 radiance를 바닥 BRDF의 specular 항에 통합 |
| 버전 | 최종 모델과 베이크 시점 불일치 | author/baked .blend·생성 스크립트·모델/노멀/GI/HDR 파일의 해시 기록 |

확산광은 progress 0 / 0.65 / 1의 안정 상태에서 각각 계산합니다. 그 사이의 간접광은 보간하고 짧은 입장 모프에는 안정 상태의 조명을 사용하므로, 연속 구간과 입장 중 그림자 정합성은 이후 실제 동작 영상에서 별도로 검수해야 합니다. 금속의 HDR probe와 바닥의 평면 반사는 원본 경로 추적과 동일한 모든 반사 경로를 재현하지 않습니다. 이를 픽셀 동일성으로 주장하지 않습니다. 기존 HyperFrames 영상은 광선의 작은 emissive 변조에만 사용하며, 이 작은 시간 변화까지 간접광을 매 프레임 다시 계산하지는 않습니다.

## 원본과 처리 자료

정상 진행 중인 베이크를 중단하거나 중복 실행하지 않았습니다. 이 환경의 Blender는 내장 OpenImageDenoise가 없어 [공식 OIDN 2.5.1](https://www.openimagedenoise.org/downloads.html) CPU 도구를 임시 작업 폴더에 별도 준비했습니다. [CLI와 필터 문서](https://www.openimagedenoise.org/documentation.html)를 확인했습니다. 프로젝트 패키지에는 추가하지 않았습니다.

- 확산광: 원시 EXR 보존 → OIDN RTLightmap 처리 → 같은 선형/저장 단위로 EXR 저장.
- 원본 비교 이미지: Cycles CPU 64 samples raw / 선형 EXR 보존. OIDN RT 처리본은 별도 이름으로 구분합니다.
- 실제 웹: Chromium Playwright의 가공하지 않은 브라우저 스크린샷입니다. 원본 DCC 렌더를 웹 배경으로 덧씌우지 않습니다.
- 승인된 얼굴 자산은 재생성하거나 수정하지 않았습니다. Blender에서는 원본 이미지가 카메라/반사 광선에 보이며, GI에는 원래 형태의 alpha 가림판으로 작동합니다. 웹의 인물은 기존 toneMapped=false 규약을 유지합니다.

Blender AgX 렌더의 인물에는 DCC 뷰 변환이 적용되며, 웹의 인물은 승인된 이미지 색상을 보존합니다. 같은 원본 파일·좌표를 사용하지만 이 두 인물 패스를 픽셀 동일한 색상 결과라고 보고하지 않습니다.

## 검수 범위

1920×1080의 Hero 안정 구도, 전환 중간, 도착 구도를 실제 웹과 Blender의 같은 카메라에서 비교합니다. 원본의 투영/world 행렬과 웹 행렬, 모프 UUID/가중치, 재질·텍스처 규약을 함께 기록합니다. 페이지 전체 캡처에서는 실제 문구와 내비게이션의 충돌을 별도로 확인합니다. 단순 검사 통과를 디자인 합격으로 사용하지 않습니다.

현재 WebGL은 실제로 확인한 SwiftShader입니다. 하드웨어 GPU, 실기기 모바일, 60FPS, VRAM 사용량은 검증되지 않았습니다. Half-float GI 세 상태의 상주 메모리와 디코딩 비용은 최종 모바일 단계에서 측정·압축 검토가 필요합니다. 핵심 모프·공간 전환을 제거하는 방식으로 해결하지 않습니다.

## 보호와 다음 검수

Luna 독립 감사에서 보호 파일 2,255개가 모두 기준 해시와 일치했습니다. 게임·코어·API·라우트·번역·갤러리·편지와 package.json / package-lock.json 변경이 없습니다. 기존 verify-across-hero.mjs는 이전 Hero의 선택자·진행 길이·pointer 데이터와 영상 녹화를 전제로 하므로 이번 정적 구도 검수에는 사용하지 않았습니다. 현재 카메라·재질 계약에 맞춘 정적 캡처 및 검사로 구분합니다.

정적 구도의 총괄 검수 이후 포인터, 정방향 스크롤, 실제 모프, 다음 공간 진입, 역스크롤 복귀의 브라우저 녹화를 제출합니다. Gate 2와 새 긴 인트로 영상 제작은 진행하지 않습니다.

## 실제 비교에서 추가로 발견·수정한 사항

첫 실제 웹 캡처에서 바닥 반사 투영과 왼쪽 곡면 밝기 차이가 드러났습니다. 해당 실패 캡처를 별도 보존하고 아래를 수정했습니다.

1. Three Reflector의 textureMatrix는 반사 평면 자체의 변환까지 포함합니다. 이를 다른 바닥의 월드 좌표에 그대로 곱한 중복 변환을 제거했습니다. GPU에 전달된 월드 투영 행렬을 원래 평면 행렬의 역변환 결과와 대조했습니다. 실제 Slate 바닥 상단 -3.32에 반사 평면도 맞췄습니다.
2. 중앙 HDR 프로브가 왼쪽 wine 곡면의 위치별 가림을 반영하지 못했습니다. 환경 반사를 끈 진단에서 확산광 전달은 정상임을 확인했고, 같은 원본 장면의 (-10,-2.7,-5) 위치에서 32 samples 로컬 HDR을 추가했습니다. 재질 색·거칠기·반사 강도는 보정하지 않았습니다. wine 재질은 이 프로브를 사용하고 다른 재질은 중앙/도착 프로브를 사용합니다. 원본 geometry와 GI·normal 파일은 바뀌지 않았습니다.

| 기준 좌표의 선형 Red | 중앙 프로브 진단 | 로컬 프로브 진단 | 원본 Cycles raw |
|---|---:|---:|---:|
| (100,850), wine | .1637 | .0203 | .0144 |
| (400,700), wine | .1072 | .0164 | .0077 |

웹 숫자는 같은 시야의 960×540 진단에서 1920 기준 좌표를 환산해 float GPU readback한 값입니다. 최종 스크린샷의 픽셀 동일성을 의미하지 않습니다. 반사를 끈 진단은 원인 분리용이며 제품에 적용하지 않았습니다. 원본과 수치가 같다는 주장도 하지 않습니다.

바닥 반사는 현재 원본보다 선명합니다. 다음 폴리시에서 거칠기와 연결된 planar radiance 필터링과 BRDF 처리를 보완합니다. 원본 경로 추적과 모든 반사 경로가 동일한 것으로 처리하지 않습니다.

노이즈 처리의 첫 자동 호출은 상대 경로를 찾지 못해 실행 전에 실패했습니다. 절대 경로로 수정하고 실패한 후속 단계부터 재개했습니다. 원본 베이크·HDR·모델을 다시 계산하지 않았습니다. 실제 페이지 스크롤 캡처는 SwiftShader에서 스크럽 수렴이 느려 최초 30초 제한에 걸렸으며, 기다리는 시간을 늘려 실제 진행값이 수렴한 화면을 확보했습니다. 동시 CPU 렌더가 있는 이 결과를 하드웨어 GPU FPS로 환산하지 않습니다.

## 다음 동일 콘셉트 폴리시 — 승인된 검수 지시

시각적 승인은 아직 없습니다. 현재 R6 비교 자료를 보존한 뒤 다음 세 항목을 구현합니다.

- 카메라 전진 전에 오른쪽 자유단과 왼쪽 wing이 충분히 열려 목적 공간이 화면 절반 이상 드러나는 구도. 양쪽 벽은 전경 가장자리로 남고 카메라는 통로 중심으로 이동.
- 고립된 두 리본을 실제 천장 캐노피와 낮은 바닥 단으로 연결. 깊은 측면 alcove와 빛이 들어오는 개구부로 앞·중간·뒤 세 층을 만들고 Hero에서도 일부 노출. 산발적인 소품 추가 없음.
- 인물 절단면은 계속 가리면서 하단 bank와 두 번째 판의 화면상 면적 축소. 인물 뒤 벽의 곡률·측광으로 큰 명암 흐름 생성. 얼굴 원본 보존.

수정 전후는 고정된 같은 카메라에서도 비교합니다. 최종 긴 영상은 정적 검수 이후로 미룹니다.
