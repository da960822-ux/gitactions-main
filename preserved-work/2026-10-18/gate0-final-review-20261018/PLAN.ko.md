### 5.1 좌표와 상태 규약

다음 모든 시간/좌표/예산은 **설계 초깃값**이며 실측이 아니다. 단위는 world unit, +Y 위, 카메라는 -Z 방향을 바라본다. 인물 중심 `(0.7,0.1,0)`, 발/절단 경계 접지 y=-2.2, 입구 경계 z=-4, 다음 공간 중심 z=-8. 좌측 카피 safe-zone은 화면 x 6–43%, 얼굴 영역 x 53–76%, y 17–48%를 목표로 한다. 원화 하단 잘림은 무대 lip 뒤로 자연스럽게 숨긴다. 옆모습이 없는 평면의 한계를 존중해 안정 인물 관찰각은 정면 기준 ±10° 이내로 제한한다. 공간 이동은 인물 옆을 지나되 초기에 얼굴을 비틀지 않는다.

### 5.2 Mesh·법선·카메라 상세

판은 TubeGeometry를 사용하지 않는다. 같은 vertex 수/UV를 가진 3가지 shape target(접힌 무대, 열린 입구, 내부 벽)을 authoring하고, 접힘부는 piecewise hinge rotation으로 계산한다. 큰 굴곡은 좌표 보간만 하면 두께가 꺼질 수 있어 중앙 surface와 edge shell을 동일 deformation 함수로 움직인다. 법선은 변형 미분/analytic normal 또는 저빈도 CPU 갱신을 비교해 확정한다. 표면 UV가 뒤집히거나 자가 교차하지 않는 p=.25/.5/.75를 별도 검수한다. world-space roughness/브러시 방향이 늘어나지 않도록 object basis 또는 보정 UV를 적용한다.

카메라는 control point 기반 Catmull-Rom 위치 곡선과 별도 lookAt 곡선으로 이동하되 입구 모서리에서 벽 관통 여부를 체크한다. FOV 확대를 이동처럼 쓰지 않는다. near=.1, far=80 초깃값; 인물 plane과 영상 plane의 coplanar z-fighting 금지. 인물은 진짜 3D 두상이라고 소개하지 않는다. 원본 alpha silhouette를 이용한 접지·rim wrap와 실제 공간 occlusion만 부여한다. 평면 약점이 노출되면 원본을 훼손하지 않는 layered silhouette/depth 자산을 별도 승인 후 제작한다.

### 5.3 영상↔WebGL handoff 계약

composition과 월드는 동일한 camera intrinsics, object transforms, linear/sRGB 처리, ACES exposure, viewport crop 정보를 담은 설계 manifest를 공유하도록 한다. Remotion intro 최종 frame 95(30fps·3.2초 목표)와 live H2의 안정 pose(p=0)를 동일 구도로 맞춘다. H0/H1/H2의 t는 같은 0–3.2초 첫 등장 타임라인이며 영상 마지막에 두 번째 entry를 재생하지 않는다. Skip은 현재 live pose에서 H2로 짧게 수렴한다. 1920/1440/390별 match frame을 비교하고 윤곽 이동 ≤2 CSS px·눈에 띄는 명도 점프 없음은 초기 품질 목표다. 수치만 만족해도 눈으로 보이는 seam이 있으면 불합격.

현재 자산은 동일 카메라 manifest로 만든 것이 아니므로 재사용을 기본값으로 삼지 않는다. 새 최종 프레임이 맞지 않으면 영상/lighting을 다시 제작한다. 영상 autoplay 거절/느린 decode 시 live 동일 pose가 처음부터 보이며 사용자 콘텐츠와 CTA는 항상 DOM에 있다. 전환을 화면 fade로 바꾸지 않는다. H4의 video는 장면 자체가 아니라 live mesh의 내부 재질이며 camera/parallax/occlusion은 계속 실시간이다.

## 7. 기술·도구의 실제 상태와 담당

### 7.1 구조 선택

**React 19 + TypeScript + 기존 직접 Three.js + GSAP ScrollTrigger**를 유지한다. R3F는 현재 의존성에 없고 직접 Three 코드가 이미 있으므로 도입하지 않는 안을 추천한다. 실제 3D, shader, morph, 카메라 요구는 직접 Three로 모두 수행한다. 엔진 교체가 품질을 보장하지 않는다. Motion/Anime 등을 중복 설치하지 않는다.

Gate 1의 예상 변경 경계는 `AcrossHero`, hero CSS, `cinematic/across-world`와 새 Hero 전용 pose/geometry/material 모듈, 필요한 영상 composition/자산, Hero 검증 스크립트다. `Landing`은 연결에 필요한 최소 변경만 허용. 게임 엔진·core API·Supabase·피드백 내용·rhythm·기존 편지 원문은 금지 경계다. 호출부는 `Landing → AcrossHero → createAcrossWorld`; tests/captures는 Hero 파일을 참조하며 cleanup/StrictMode mount·unmount도 검증한다. 다른 Gate 컴포넌트는 이때 구현하지 않는다.

### 7.3 상태·수명·오류

`intro: unseen/loading/playing/skipped/done`, `scene: hero/story/portal/gallery/letter/end`, `letter: closed/opening/open/closing`, `selectedGame`을 구분한다. p는 ref/uniform, 언어·선택·편지 상태만 React state. state마다 하나의 소유자. 스크롤은 콘텐츠 선택을 바꾸지 않는다. WebGL context lost 시 이미지/DOM 전체 접근과 진입 링크를 유지하고 복원 시 현재 p·selected를 다시 평가한다. 이것은 오류 복구 경로이며 모바일 정적 축소안이 아니다.

Page Visibility/IntersectionObserver로 비활성 렌더·decode 중지. re-entry에서 큰 dt 누적 금지. load 오류는 console 은폐하지 않고 자산 상태/재시도를 기록. Texture/material/geometry/video/GSAP timeline·observer·event listener를 dispose. 두 번 방문 후 GPU 메모리 단조 증가, 중복 RAF/ScrollTrigger를 확인한다.

## 8. 게임·기능 안전 보존 및 연결 전략

**지금은 게임 브랜치 병합·cherry-pick·reset·푸시를 하지 않는다.** 원격 미푸시 커밋을 이 환경에서 복원 가능하다고 가정하지 않는다. 게임 담당 작업이 조커 교체를 끝내고 사용자가 승인한 handoff SHA/branch 또는 bundle을 제공해야 통합 검증을 시작할 수 있다.

후속 통합 순서: (1) 게임 담당이 최신 미푸시 커밋·working tree·자산·parent SHA 목록 및 bundle/원격 전달 경로를 보존한다. 그 작업의 파일을 대신 편집하지 않는다. (2) 해당 불변 SHA를 새 독립 통합 브랜치의 기준으로 삼을지, 서로의 공통 조상을 기준으로 랜딩 한정 커밋만 올릴지 ancestry/diff로 결정한다. (3) 랜딩 작업은 승인된 게임 baseline에서 별도 worktree로 하고 manifest/lock 공통 파일은 양쪽 dependency를 조정한다. (4) src/app/core/games/supabase/public 게임 자산은 게임 담당 소유로 대조하고 랜딩 전체 덮어쓰기를 금지한다. (5) 보호 파일 sha256·route 목록·letter strings를 전후 비교하고 충돌은 hunk별로 해결한다. (6) 통합 테스트와 실제 두 사용자 흐름을 확인한 뒤 사용자의 명시 승인. main merge/배포는 별도 권한 없이는 수행하지 않는다.

현재 8개 id/진입: `davinci`, `catchmind`, `domino`, `jaipur`, `splendor`, `minhwatu`, `marble`, `rhythm` → `/play?game={id}`. 게임방 `/room/{id}`, 로비 `/play`, 최상단 `/feedback`, hash `#games`/`#papi-letter` 보존. 해시 직접 방문 시 intro를 건너뛰고 목적지에 안정 착지. 새로고침·뒤로가기·초대 링크도 동일 계약.

`dos-language`는 `ko`/`es`, 문서 lang은 `ko`/`es-DO`. 선택 언어가 `/play`, room create/join과 게임 API의 player language로 이어지는지 확인한다. `catchmind.ts`는 `answers(c)=[c.ko,c.es].map(norm)`과 `isCorrectGuess`로 이중 정답을 확인했다. 이를 랜딩 변경에서 건드리지 않고 KO/ES 실제 입력 회귀를 계획한다. 기존 채팅 번역 문구는 캐치마인드 전용이고 한도/원문 fallback 설명이 존재한다. 공통 번역 채팅으로 확대하지 않는다.

기존 편지는 한/스페인어 5문단·제목·서명·접기 라벨을 literal 보존한다. 새 story 카피는 별도 키에 두어 `home.ts` 전체 교체로 편지 원문이 바뀌지 않게 한다. 건의사항 페이지 기존 문구/데이터/API/권한/무료 티어 guard와 초대·게임 흐름을 보존한다. 모바일 게임 진입 가드는 현재 정책을 그대로 두며 랜딩 개선을 모바일 게임 개발로 확장하지 않는다.

[Refero](https://refero.design/)는 이 도구의 텍스트 추출이 비어 개별 화면 분석은 미완료다. [Paired](https://www.paired.com/)와 [Life360](https://intl.life360.com/) 공개 페이지는 열람했지만, 친밀함·거리 연결이라는 맥락만 참고하고 상담·질문·위치추적을 새 기능으로 소개하지 않는다. Lazyweb/WebsitePrompts.ai/InspoAI는 제공 명칭의 사이트 접근을 시도했으나 이 도구에서 열리지 않아 구도·타입·모션을 보았다고 주장하지 않는다. Inspo MCP는 현재 도구에서 찾지 못했다. 이 후보는 후속 reference board의 미완료 조사 항목으로 남기며 부재 때문에 핵심 효과를 제거하지 않는다.

Lusion 공식 페이지와 Landing Love 소개는 이번에 열람했다. 원본 후보 `cdn.landing.love/videos/lusion.mp4`는 이 도구에서 접근되지 않았다. 따라서 위 타임코드 표는 **사용자 제공 분석을 요구 검증으로 옮긴 것**이고 원본 실제 시청 완료가 아니다. 접근 가능한 원본을 확보하면 Gate1 시각 비교 전 지정 구간별 카메라/법선/오클루전/오브젝트 계보를 프레임 단위로 재검토한다.

Bruno Simon은 reference·이미지·코드·구도·모션 분석 모두에서 제외한다. 레퍼런스를 직접 복제하지 않으며 이름만 나열하고 사용했다고 보고하지 않는다.

## 11. 성능·모바일·접근성 전략

### 11.1 목표 예산 — 미실측

| 항목 | 초기 설계 목표 | 측정 및 초과 시 대응 |
|---|---|---|
| 프레임 | GPU 가속 desktop 60fps 우선, 평균 frame≤16.7ms 목표·p95≤25ms 목표; mobile 60fps 지향, 실제 결과 공개 | GPU 명칭/브라우저/OS/DPR/해상도/refresh/녹화 on-off 기록. rAF는 프레임 간격이지 GPU time 아님. 지원 시 disjoint timer query 별도 |
| CPU/long task | 정상 scroll 동안 50ms 이상 long task 반복 0 목표 | Performance trace에서 shader compile/decode/layout/GC 분리. 로딩중 compile warmup, frame state를 ref/uniform에 기록 |
| draw/triangles | Hero ≤100 draw / ≤180k visible triangles 목표, gallery ≤150 draw / ≤250k 목표 | renderer.info 실측; instance·merge·culling·static baked light. 효과 삭제 대신 동일 외형 비용 감축 |
| texture/GPU | 활성 texture 추정≤96MB desktop / ≤48MB mobile 목표 | 압축 파일 크기와 VRAM 추정 별도. 2K RGBA 16MiB/mip 약21.3MiB를 인지, KTX2 지원 검증·atlas/LOD |
| DPR | desktop 1–1.5, mobile 1–1.25 초깃값 | GPU 측정 기반 adaptive DPR, 목표 충족 후 천천히 회복·hysteresis. 밝기/재질/씬 자체를 제거하지 않음 |
| 영상 | 동시에 decode 1개 기본, 전환 중 짧게 2개 상한 목표 | requestVideoFrameCallback, readyState/dropped frames/media trace, 8 preview preload 금지, poster/짧은 GOP/구간 cache |
| 초기 전송 | critical HTML/CSS/JS/font/portrait 합계 gzip 등 측정 기준 명시 후 ≤3.5MB 목표; decorative film 지연 로드 | 실제 waterfall/LCP/CLS 기록. LCP≤2.5s·CLS≤.1·INP≤200ms는 지정된 네트워크/기기 목표, 달성 주장 아님 |

WebGL 임시 메모리·프로그램 수·context 손실·shader compile도 확인한다. 상대 성능은 같은 기기·같은 scroll script·같은 viewport에서 baseline과 비교한다. 소프트웨어 클라우드만 있으면 정확한 그 결과를 공개하고 hardware gate는 미검증으로 둔다. CPU throttle을 mobile GPU 대체 증거로 쓰지 않는다.

최적화 우선순위: 과도한 shader 분기·실시간 굴절 pass→환경맵/베이크·실시간 한정 하이라이트, 법선 재계산→GPU analytic normals, 중복 object→instancing, texture→KTX2/LOD, DPR 조정, 의미 없는 반복 render/영상 decode 중지, 사전 렌더 가능한 상세 motion→영상 surface. 외형·인물 중심·공간 연속성이 떨어지는 대안은 비교 영상을 제시하고 사용자의 명시 승인 전 채택하지 않는다.

### 11.2 모바일

desktop Hero 품질·모션을 먼저 승인받고 Gate 6에서 본 구현을 확장한다. 다만 좌표/자산/메모리 설계는 지금 모바일 제약을 반영한다. 390×844에서는 카피 상단 약 36%, 원화 하단 약 46% 중심으로 재구성하고 얼굴/CTA 겹침을 방지한다. `svh/dvh` 주소창 변동, safe-area, 세로/가로 전환을 처리한다. 모바일에서도 판의 실제 접힘·원근·camera 진입·선택형 3D gallery·letter 개봉을 유지한다. hover 대신 tap/drag와 DOM controls; drag threshold로 수직 scroll 방해 금지. 절대축소된 desktop full viewport를 crop하지 않는다.

기본 모바일 연출과 `prefers-reduced-motion`은 구분한다. 후자는 사용자 접근성 선택이므로 pin/대규모 camera motion을 완화하고 동일 내용과 읽기·선택·개봉 상태를 제공한다. 이 변형을 일반 모바일 연출로 적용하지 않는다. WebGL 미지원/오류/데이터 절약 상황의 기능 fallback은 별도 명시하며 최종 시각 경험 완료로 대신 제출하지 않는다.

### 11.3 DOM·접근성

h1 하나, 장면별 h2와 의미 순서 유지. WebGL은 묘사 label 또는 decorative aria-hidden으로 중복 낭독 방지. 실제 카피·편지·정답 설명은 DOM이고 영상/텍스처에만 넣지 않는다. 일반 텍스트 대비 4.5:1·큰 글자 3:1 목표, focus ring/터치 타깃 최소44px 권장. Canvas의 pointer 장난이 CTA 이벤트를 가로채지 않게 한다. 건너뛰기, pause, letter open/close는 keyboard/Enter/Space/ESC 및 올바른 expanded/controls. 언어 변경은 focus/selected/scroll state를 유지하고 긴 ES에서 overflow 검사. 읽는 동안 문단이 떠다니거나 사라지지 않는다.

## 13. 브라우저 검수: 기능 합격과 미적 합격 분리

### 13.1 증거 수집 절차

1920×1080을 우선으로 1440×900, 390×844 각 raw recording을 별도 제작한다. recordVideo size=viewport, browser zoom100%, DPR와 renderer 기록. 최초 방문은 storage 비움, 재방문은 유지한 별도 케이스. 영상을 편집하지 않고 최초 진입→입장 전체→안정 3초→pointer 4방향→p 0/.2/.45/.72/1→내부 통과→역행→복원 Hero를 순서대로 담는다. 하이라이트 편집본·Remotion export와 파일명/폴더를 분리한다.

## 15. 최종 납품과 지금 승인받을 것

전 Gate 사용자의 명시 승인 후만 최종 결과로 제출한다: (1) desktop 전체 raw browser 영상 (2) Hero 실제 interaction (3) 핵심 transition (4) gallery 사용 영상 (5) letter 개봉 영상 (6) mobile 주요 장면 (7) Remotion/HyperFrames 실제 제작 source/export (8) 실제 사용 skill/tool/version (9) 수정 파일/component/SHA (10) 성능 결과/환경 (11) 기능 결과/실패 (12) 신규 자산/권리/잔여 문제. 원본 실행 영상과 편집 highlight를 구분하고 미구현 효과를 편집 영상으로 완료 처리하지 않는다.

부록 `REQUIREMENTS-TRACE.ko.md`는 원문 요구를 ID로 분해하여 대응 절·실제 선택·근거·검증·승인 시점을 연결한다. 요구 존재를 확인한 것이지 구현 충족 판정이 아니다. 이 계획이 원문보다 구체적인지는 ‘각 장면의 전후 geometry/카메라/입력/역행/영상 handoff/DOM 계약’, ‘명시된 보호 경계’, ‘실측과 목표의 분리’, ‘Gate별 증거와 불합격 조건’으로 검토한다. 길이로 품질을 대신하지 않는다.

지금 사용자에게 제출하는 검토 대상은 **A안 추천을 포함한 Gate 0 계획 전체와 요구 추적표**다. 사용자의 계획 통과·구현 시작 지시는 다음 **Gate 1 Hero와 직접 연결되는 진입·공간 전환** 착수 경계다. 이번 승인은 자동 완성 지시로 해석하지 않으며, 각 Gate의 실제 증거와 사용자 명시 승인을 생략하지 않는다. 이 문서를 제출한 뒤 임의로 구현을 시작하지 않는다.

확인하지 못한 것: 기존 앱 전체 브라우저 녹화, 2023 원본 레퍼런스 영상, 미푸시 게임 최종본, 실제 GPU 성능. 남은 위험은 제14절에 명시했다.

Gallery 자체를 지금 추출하거나 수정하지 않는다. 화면이 비슷한 두 canvas를 fade로 교체하는 구조는 기본안에서 제외한다.

### 16.2 영상·실시간·DOM 소유권

Remotion은 웹과 같은 순수 Three scene factory·pose·materials·framing을 import하는 canvas adapter로 프레임을 만든다. 새로운 R3F/@remotion/three 설치를 기본값으로 삼지 않는다. `frame/fps`를 명시 입력하고 texture/환경/폰트 준비·해당 프레임 실제 렌더 완료 전 `delayRender`를 유지한다. 실패는 `cancelRender`·로그로 남긴다. frame 순서를 바꿔 캡처해도 같은 pose인지 비교한다.

video에는 메인 카피·CTA를 굽지 않는다. 인트로 중 영상 속 원화/공간과 실시간 원화/공간은 동시에 중복 노출하지 않는다. 마지막 decoded frame과 live 동일 pose가 준비됐을 때 한 tick에서 픽셀 소유권을 넘긴다. DOM h1/본문/CTA/Skip은 같은 요소로 유지한다. autoplay 거절·Skip·scroll interrupt는 같은 live scene의 entry/현재 scroll pose로 수렴한다. Remotion export가 없으면 fallback만 성공했다고 명시하며 실제 제작 완료로 보고하지 않는다.

모든 공통 입력은 `introTime`, `sceneProgress`, `letterPhase`, `pointer`, `viewportProfile`로 분리한다. 이벤트에 동기화된 영상은 `T_i(p)=clamp((p-a_i)/(b_i-a_i),0,1)*duration_i`로 seek하며 autoplay와 scroll이 동시에 시간을 쓰지 않는다. 최근 seek generation만 유효하고 geometry는 오래된 decode callback에 의해 역행하지 않는다. requestVideoFrameCallback/readyState로 decoded frame을 확인한다. 비사건성 광택 디테일 loop는 명시적으로 별도다.

출력색·tone mapping·exposure·색 텍스처 sRGB/normal linear를 web/export에서 고정한다. 현재 ACES 유지와 대체 tone mapper를 임의 혼용하지 않고 승인 시 look test 하나를 선택한다. PNG 일치와 실제 decoded MP4 BT.709/sRGB 변환 일치를 별도 검증한다. 얼굴·금속·회색·검정 crop을 직접 본다. 1920×1080/1440×900/390×844별 framing을 사용하며 다른 aspect를 cover한 흔적을 fade로 숨기지 않는다. 2 CSS px 윤곽 오차는 초기 점검 목표이며 눈에 보이는 seam이면 수치와 관계없이 불합격이다.

### 16.3 조명·재질의 실측 가능한 계약

명목상 PBR만 붙인 플라스틱 재발을 막는다. 원화 key 방향에 맞춘 넓은 주광, burgundy 반사면, cold depth/rim, 실제 열린 틈으로 들어오는 빛을 구분한다. 금속 단면의 두께·roughness·normal과 넓은 무광 면을 따로 authoring한다. floor reflection은 실제 반사 geometry/공간과 맞고 재질 roughness에 맞는 blur를 가진다. 바닥보다 아래에 반사면을 두거나 model/world matrix를 중복 적용하는 오류를 방지한다.

GI/환경맵을 베이크한다면 각 receiver UV/법선/color space/flip 방향, albedo 포함 여부와 irradiance 단위를 manifest로 고정한다. material을 공유해 다른 면 atlas가 새는 것을 금지한다. 형상 상태별 조명 표본과 스펙큘러 probe가 실제 개방 상태를 반영하는지 검사한다. 같은 source·같은 camera·같은 pose의 authoring renderer와 실제 Three 캡처를 비교해 기술 불일치와 미적 문제를 분리한다. 샘플 수만 올려 조형·열린 공간·구도 문제를 해결했다고 주장하지 않는다.

### 16.4 독립 게임 작업 보존: T0/T1/T2

**T0 승인 후 Hero 착수 전:** 랜딩 기준 24a6ec6에서 새 격리 작업선을 만들고 게임/core/API/Supabase/rhythm/이미지/letter/feedback/언어/route의 파일 hash와 문자열·경로 계약을 고정한다. 기존 후속 랜딩 worktree를 파괴적으로 reset하거나 승인 없는 구현을 채택하지 않는다. 독립 게임 작업의 파일·프로세스·조커 교체를 건드리지 않는다.

**T1 게임 담당 인계본 도착 후:** 사용자 메시지의 3972aa4/ec08555는 미푸시 로컬 커밋으로 취급한다. 이후 최종 SHA/작업 상태/원본 자산/부모 커밋/working tree 포함 여부를 담당의 인계 기록으로 확인한다. 전달 bundle은 프로젝트 밖에서 checksum, `bundle verify/list-heads`, prerequisite, 별도 clone/fsck 및 파일 목록을 검증한다. 현재 원격에 없는 변경을 복원됐다고 주장하지 않는다. 기존 선행 자료에 후속 게임 bundle 언급이 있더라도 이번 직접 bytes 검증을 대신하지 않는다.

**T2 늦어도 Gate3 기능 통합 승인 전:** 확정 게임 기준 G의 별도 통합 branch에 승인된 landing 한정 변경을 적용한다. 공통 app shell/catalog/copy/manifest/lock 충돌은 ancestry와 hunk별 의도로 해결하고 전체 랜딩 branch로 덮어쓰지 않는다. game/core/API/자산은 G와 hash 대조한다. 통합 전후 8게임×2언어, 로비/초대/뒤로/새로고침, 캐치마인드 이중 정답, letter 원문, feedback 링크·문구, rhythm 원본을 회귀 검증한다. 통합 허가나 인계본이 없으면 ‘최신 게임 연결 합격’을 보류하며 시각 QA로 대신 인증하지 않는다.

Hero 격리 구현 자체는 게임 인계 완료를 기다릴 필요가 없지만 **Gate0 승인 전에는 시작하지 않는다.** push·deploy·게임 담당 변경은 이 계획의 승인 범위로 자동 포함되지 않는다.
