## 현재 코드에서 확인한 범위

`src/landing/AcrossHero.tsx`는 GSAP/ScrollTrigger와 `previewSpaceV19.createFoldedWorld`를 연결한다. 현재 진행률/등장/포인터를 단일 pose에 전달하며, WebGL 컨텍스트·리사이즈·가시성 정리와 DOM CTA가 있다. V19는 동결 WIP이며 승인 결과가 아니다. `previewSpaceV19.ts`에는 WebGLRenderer, 별도 Hero 인물 rig, 곡면 변형·영상 표면·반사·도착 공간이 있으나 기존 회색 공간을 새 방으로 인정하거나 색만 바꿔 재사용하지 않는다.

기존 `GameGallery.tsx`는 별도 StudioScene·8개 게임 선택·`/play?game=${selected}` 연결을 담당한다. Hero가 해당 선택 상태나 게임 엔진을 재구현하지 않는다. 캐치마인드의 `CatchmindTable.tsx`에는 실제 그리기/맞히기 역할과 KO/ES UI가 있다. 모니터 콘텐츠는 이 실제 구현의 승인된 버전에서 취득해야 한다.

소스는 승인 후 Hero 담당의 별도 접두 경로에만 추가하고, 게임/이후 장면 담당과 파일 목록을 교환한다. 기존 V18/V19, 기존 승인 Hero 원화, A 정적 시안은 삭제·덮어쓰기하지 않는다. 새 패키지는 현재 필요성이 확인되지 않았으며 설치 계획도 확정하지 않았다.

## 자산 분리안

1. **보존 원본:** 두 Library 파일을 원본 그대로 유지하고 ID·버전·해시·승인 범위를 기록. 픽셀 확보 전 해시·알파를 추정하지 않음.
2. **게임방 clean plate:** 캐릭터·모니터 화면·타이포가 없는 공간 배경. 최종 방 이미지 전체를 하나의 평면에 붙여 카메라만 확대하는 구현은 불가. 실제 벽·책상·창·의자·광원은 3D 자산으로 분리.
3. **캐릭터:** 두 사람 별도 투명 PNG/WebP, 권장 각 인물 높이 2048px 이상. 머리·몸·팔·손·헤드셋의 분리가 필요하면 원본 얼굴을 다시 그리지 않는 편집 자산을 준비. 분리 불가능한 단일 그림은 미세한 표정/팔 연기와 제한된 시점의 한계가 있으므로 승인 없이 3D 캐릭터라고 부르지 않는다. 충분한 카메라 회전에는 승인된 추가 시점이나 동일 얼굴의 모델/리그가 필요하다.
4. **화면:** 모니터 두 개의 프레임/베젤/표시면을 각각 독립 메시·UV로 제작. 1920×1080 또는 1280×720의 실제 게임 캡처와 짧은 실제 플레이 영상을 사용. 렌더용 장면 이미지에 포함된 가상 UI는 최종 사용 금지.
5. **보조 자산:** 방 재질, 로즈골드 반사, 버건디 패브릭, 서로 다른 벽/조명, 의자·PC·키보드·마우스. 장소 고정관념이나 실제 방 재현 주장은 금지. 원본 확보·방 승인 뒤 실제 필요한 자산만 확정.

## 연속 공간 전환 스토리보드

아래 수치는 타이밍 설계용 정규 진행률이며 아직 실측·구현되지 않았다.

- **0–0.18 / A의 안정 Hero:** 승인 우주 첫 화면, 기존 커플 중심·메인 카피·CTA. 포인터는 짧고 감쇠된 카메라/빛 반응을 만들고 인물 얼굴을 왜곡하지 않는다. 안정 구도에서는 인물이 시각 중심.
- **0.18–0.42 / 물성 변화:** 전경의 로즈골드 경계와 표면이 서로 다른 축으로 휘어 벌어진다. 동일 topology/UV 표면의 안쪽은 책상 선으로 이어진다. 앞/뒤 물체 속도·오클루전·반사 방향이 달라 실제 깊이를 보여준다. Hero 커플은 최초 공간에 남아 카메라를 따라오지 않는다.
- **0.42–0.68 / 통과:** 카메라가 열린 경계의 테두리를 지나간다. 두 방의 실제 벽·책상·의자·광원이 시야 안에 새로 들어온다. 우주 배경을 방 벽에 반복하지 않는다. 중앙 seam은 두 공간을 물리적으로 한 방이라고 속이는 대신 연결의 구조로 보인다.
- **0.68–1 / 두 방 도착:** 방마다 다른 분위기와 같은 게임을 하는 승인 캐릭터를 보여준다. 큰 머리/작은 몸·최신 실제 의상을 유지. Lisbeth의 신난 표정과 Yeonseok의 미소·집중, 손/시선/모니터 방향을 함께 검수. 중앙 책상선과 동기화된 실제 게임 화면이 온라인 연결을 드러낸다. 도착에 필요한 캐릭터는 새 게임 포즈이며 Hero 원화를 복제해 쫓아오게 하지 않는다.
- **역스크롤:** 같은 진행률 함수·카메라·공유 메시를 역행. 애니메이션 시작/종료 이벤트만으로 상태를 바꾸지 않는다. 영상은 seek 완료와 실제 표시 프레임을 확인하고, 텍스처 준비 전 카메라가 빈 공간에 진입하지 않도록 한다. Hero로 돌아오면 최초 인물·광원·CTA가 복원된다.

## 실제 게임 화면 취득과 언어

게임 담당의 승인된 최신 수정본을 변경 없이 확인한 뒤, 테스트용 두 클라이언트의 같은 라운드를 녹화해 드로어/추측자 역할과 화면을 일치시킨다. 한국어·도미니카 스페인어는 기존 실제 UI/정답 판정 계약을 따른다. 편의상 두 화면을 모두 동일한 가짜 그림으로 채우지 않는다. 계정·채팅 개인정보 없는 테스트 콘텐츠를 사용하고 방의 장식적 프리뷰와 클릭 가능한 실제 게임 진입을 구분한다. 랜딩이 실제 방에 접속하거나 사용자 대국 데이터를 읽도록 만들지 않는다. 리듬타파 원본 수정 없음.

## 승인 순서와 검수

1. 두 원본 파일의 픽셀 확보 → 메인의 얼굴·의상·레이아웃 직접 확인. 현재 여기서 차단됨.
2. 사용자의 방 시안 승인. 캐릭터 승인만으로 방 적용 승인으로 확대하지 않음.
3. 승인 방과 일치하는 분리 자산/게임 포즈/실제 모니터 화면의 큰 정적 합성 확인.
4. 선택된 Hero와 직접 연결되는 공간 전환만 구현. 다른 Gate 구현 금지.
5. 1920×1080 실제 브라우저 진입·포인터·정방향·중간 변형·통과·도착·역방향·Hero 복귀 녹화와 큰 캡처 제출. 1440×900/390×844에서도 읽기·얼굴·CTA·언어·내비 점검. 사용자 승인 전 Gate 1 완료 아님.
6. GPU 가속 여부를 확인하고 실제 프레임 타임·decode·drawcalls·texture/geometry 자원을 측정. 기존 SwiftShader 결과로 실제 GPU 성능을 추정하지 않음. 적응 DPR·KTX2·LOD·정적광 베이크·재질 최적화를 우선 검토하되 핵심 공간 변형을 일방 제거하지 않음.

이 문서는 계획이며 제품 적용·브라우저 실행·새 생성·게임 수정·패키지 변경은 하지 않았다. 원본 확보 및 방 적용 승인 대기.
