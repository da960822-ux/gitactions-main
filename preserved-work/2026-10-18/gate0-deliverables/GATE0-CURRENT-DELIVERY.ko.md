## 추천과 구체적인 다음 단계

A ‘우리의 접힌 극장’을 추천한다. 승인된 두 사람을 중심에 두고 얇은 접힌 표면이 무대→입구→내부 벽으로 이어진다. B ‘두 지평의 만남’은 풍경·수면이 회랑이 되는 방향, C ‘우리 둘의 빛나는 인쇄실’은 인쇄판·타입 공간이 방으로 변하는 방향이다. 세 안의 구도·색·재질·위험은 전체 계획 제4절에 비교했다.

Hero의 검토 순서는 첫 방문 3.2초 이내의 개방과 Skip→안정된 인물·타입 구도→포인터의 카메라·광원 반응→같은 topology 표면의 바닥·벽 변형→카메라가 z=-4 입구를 실제 통과→z=-7 다음 방 내부→동일 상태함수 역평가로 Hero 완전 복귀다. 시간·좌표는 설계 초깃값이며 완성도 인증이 아니다.

GSAP/ScrollTrigger는 단일 진행률과 카메라 타임라인, Three.js는 실제 geometry·법선·조명·원근·포인터를 담당한다. Remotion은 공유 Three 장면으로 인트로를 프레임 렌더해 live 마지막 프레임을 맞춘다. HyperFrames는 별도의 표면용 모션그래픽을 제작해 실제 mesh의 VideoTexture로 사용한다. 웹 실시간 효과와 편집 영상은 구분한다. Taste·Emil 지침의 조사·실제 적용·향후 적용 예정은 전체 문서 도구표에서 구분한다.

Gate 1 Hero→Gate 2 실제 이야기·영상→Gate 3 3D 게임 갤러리→Gate 4 편지→Gate 5 전체 연결→Gate 6 모바일·최적화 순서다. 각 단계는 실제 브라우저 녹화·화면 검토·수정·재검수를 거치고 사용자 명시 승인 전 다음 단계로 가지 않는다. Gate 1은 1920×1080 원본 녹화 9동작과 PNG, 1440×900·390×844 위험 점검을 제출한다. 빌드·스크린샷 존재만으로 미적 합격을 선언하지 않는다.

## 미검증과 자산 위험

- Lusion 원본 녹화는 CONNECT 403으로 이 환경에서 실제 시청하지 못했다. 타임코드 연출 분석은 사용자 제공 설명과 직접 관찰을 구분한다.
- 현재 클라우드 브라우저의 조회 결과는 SwiftShader이며 실제 GPU 가속 성능은 미검증이다. 60FPS는 목표다.
- 최종 게임 bundle의 자체 수신·복구 검증은 전송 CONNECT 403으로 미완료다. 담당자의 최종 SHA·bundle·체크섬을 보존하고 별도 복원 검증 후 Gate 3에서 연결한다. 랜딩 브랜치로 게임을 덮지 않는다.
- 기존 캐리커처는 1254×1254 투명 PNG/WebP를 우선 사용한다. 고해상도 확대가 필요하면 같은 승인 원화의 2500–4000px RGBA 또는 원본 레이어를 요청한다. 얼굴 재생성은 하지 않는다.
- 8게임에는 서로 다른 실제 대표 화면·프리뷰가 필요하다. 대표 이미지는 가로 1600px 이상을 목표로 하고, 프리뷰는 1080p·무음·짧은 길이로 별도 권리·내용을 검증한다. 저품질 임시물은 최종 사용하지 않는다.
- 기존 편지와 KO/es-DO·언어 전달·캐치마인드 양언어 정답·feedback·API·리듬 원본은 보호 경계다. 게임 담당 최종본의 보호 파일 해시와 경로 검증을 별도로 수행한다.
