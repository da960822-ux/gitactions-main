8. 게임·기능 안전 보존 및 연결 전략

지금은 게임 브랜치 병합·cherry-pick·reset·푸시를 하지 않는다. 원격 미푸시 커밋을 이 환경에서 복원 가능하다고 가정하지 않는다. 게임 담당 작업이 조커 교체를 끝내고 사용자가 승인한 handoff SHA/branch 또는 bundle을 제공해야 통합 검증을 시작할 수 있다.

후속 통합 순서: (1) 게임 담당이 최신 미푸시 커밋·working tree·자산·parent SHA 목록 및 bundle/원격 전달 경로를 보존한다. 그 작업의 파일을 대신 편집하지 않는다. (2) 해당 불변 SHA를 새 독립 통합 브랜치의 기준으로 삼을지, 서로의 공통 조상을 기준으로 랜딩 한정 커밋만 올릴지 ancestry/diff로 결정한다. (3) 랜딩 작업은 승인된 게임 baseline에서 별도 worktree로 하고 manifest/lock 공통 파일은 양쪽 dependency를 조정한다. (4) src/app/core/games/supabase/public 게임 자산은 게임 담당 소유로 대조하고 랜딩 전체 덮어쓰기를 금지한다. (5) 보호 파일 sha256·route 목록·letter strings를 전후 비교하고 충돌은 hunk별로 해결한다. (6) 통합 테스트와 실제 두 사용자 흐름을 확인한 뒤 부모 검수 통과. main merge/배포는 별도 권한 없이는 수행하지 않는다.

현재 8개 id/진입: davinci, catchmind, domino, jaipur, splendor, minhwatu, marble, rhythm → /play?game={id}. 게임방 /room/{id}, 로비 /play, 최상단 /feedback, hash #games/#papi-letter 보존. 해시 직접 방문 시 intro를 건너뛰고 목적지에 안정 착지. 새로고침·뒤로가기·초대 링크도 동일 계약.

dos-language는 ko/es, 문서 lang은 ko/es-DO. 선택 언어가 /play, room create/join과 게임 API의 player language로 이어지는지 확인한다. catchmind.ts는 answers(c)=[c.ko,c.es].map(norm)과 isCorrectGuess로 이중 정답을 확인했다. 이를 랜딩 변경에서 건드리지 않고 KO/ES 실제 입력 회귀를 계획한다. 기존 채팅 번역 문구는 캐치마인드 전용이고 한도/원문 fallback 설명이 존재한다. 공통 번역 채팅으로 확대하지 않는다.

기존 편지는 한/스페인어 5문단·제목·서명·접기 라벨을 literal 보존한다. 새 story 카피는 별도 키에 두어 home.ts 전체 교체로 편지 원문이 바뀌지 않게 한다. 건의사항 페이지 기존 문구/데이터/API/권한/무료 티어 guard와 초대·게임 흐름을 보존한다. 모바일 게임 진입 가드는 현재 정책을 그대로 두며 랜딩 개선을 모바일 게임 개발로 확장하지 않는다.

11.2 모바일

desktop Hero 품질·모션을 먼저 승인받고 Gate 6에서 본 구현을 확장한다. 다만 좌표/자산/메모리 설계는 지금 모바일 제약을 반영한다. 390×844에서는 카피 상단 약 36%, 원화 하단 약 46% 중심으로 재구성하고 얼굴/CTA 겹침을 방지한다. svh/dvh 주소창 변동, safe-area, 세로/가로 전환을 처리한다. 모바일에서도 판의 실제 접힘·원근·camera 진입·선택형 3D gallery·letter 개봉을 유지한다. hover 대신 tap/drag와 DOM controls; drag threshold로 수직 scroll 방해 금지. 절대축소된 desktop full viewport를 crop하지 않는다.

기본 모바일 연출과 prefers-reduced-motion은 구분한다. 후자는 사용자 접근성 선택이므로 pin/대규모 camera motion을 완화하고 동일 내용과 읽기·선택·개봉 상태를 제공한다. 이 변형을 일반 모바일 연출로 적용하지 않는다. WebGL 미지원/오류/데이터 절약 상황의 기능 fallback은 별도 명시하며 최종 시각 경험 완료로 대신 제출하지 않는다.

11.3 DOM·접근성

h1 하나, 장면별 h2와 의미 순서 유지. WebGL은 묘사 label 또는 decorative aria-hidden으로 중복 낭독 방지. 실제 카피·편지·정답 설명은 DOM이고 영상/텍스처에만 넣지 않는다. 일반 텍스트 대비 4.5:1·큰 글자 3:1 목표, focus ring/터치 타깃 최소44px 권장. 19. Gate 0 재검토 보완 — 기본 구조 확정 (2026-10-17)

19.1 갤러리는 하나의 지속되는 Three World 안으로 통합한다

최종 기본 구조는 랜딩 전체 단일 WebGLRenderer·Scene·PerspectiveCamera·Canvas다. 갤러리를 별도 canvas로 교차 fade하거나 비슷한 screenshot으로 치환하는 방식을 기본안으로 사용하지 않는다. LandingWorldHost가 renderer/context/resize/color/RAF·리소스 수명을 단독 소유하고, evaluateLandingPose(sceneProgress)가 camera position/lookAt/FOV를 단독 소유한다. GalleryCollection은 renderer가 없는 Object3D 그룹이다. 기존 StudioScene의 생성·재질·정규화 로직을 G3에서 그룹 factory로 분리해 같은 scene에 넣는다. 선택 조각의 장점과 8개 id를 보존하고 화면에서 기존보다 좋아졌는지 다시 검수한다. 이는 설계이며 지금 파일 추출/삭제는 하지 않는다.

좌표 기본값은 Hero/S02와 같은 world unit/+Y 체계다. 갤러리 root G=(0,0,-26). 각 게임의 선택/주변 local 배치는 기존 기준을 유지한다: selected (0,0,+1.3), 주변 z=-3.2, x/y는 기존 angle 기반 타원. 그러므로 선택 조각 global z=-24.7, 주변 z=-29.2다. gallery 안정 camera C=(0,0,-16.4), L=(0,0,-26), FOV38°로 기존 local camera 거리9.6을 동일하게 재현하는 출발점이다. 첫 baseline과 실제 가시 bounds를 비교한 뒤 부모 검수로 크기/구도를 개선한다. 화면 가장자리 조각을 단순히 더 작게 숨겨 성능을 맞추지 않는다.

S03 진행 q=0..1에서 camera는 S02 종료 (0,.2,-10)에서 gallery 안정 (0,0,-16.4)로 이동하고 lookAt은 z=-14에서 -26으로 이동한다. 이야기 표면은 같은 vertex identity로 z=-14 부근의 panel에서 z=-21 입구/선반 앞쪽을 거쳐 gallery 측벽·바닥으로 변한다. 카메라는 실제 z=-14 경계를 넘는다. gallery 그룹은 q=.35 이전 GPU compile/texture decode를 준비하고, 실제 geometry는 내부에 존재하여 입구가 열리며 드러난다. 별도 bitmap snapshot으로 교체하지 않는다. q=.92부터 raycast/keyboard 선택 소유권을 gallery에 전달하고 q<.88 역행 시 raycast를 해제한다(hysteresis 초깃값). 19.2 Remotion은 실제 공유 Three scene을 프레임별로 렌더한다

기본 경로: 동일한 순수 scene factory + 동일 pose evaluator를 실시간 웹과 Remotion canvas에서 import한다. 카메라 수치만 비슷하게 기입한 별도 SVG/2D intro를 만들지 않는다. 현재 쓰지 않은 @remotion/three를 새로 도입하는 것도 기본안이 아니다.

예정 공유 경계는 src/landing/cinematic/shared/{scene-assets,scene-factory,pose,materials,framing}.ts다. 실제 파일명은 G1 diff에서 확정한다. 이 계층은 React·ScrollTrigger·window 시간·포인터 이벤트·HTMLVideoElement를 직접 참조하지 않는다. 입력은 assets/quality profile/viewport spec/명시적인 pose, 출력은 scene/camera/group/material handle/dispose다. environment PMREM 생성만 adapter가 제공하는 renderer를 명시 주입한다. 렌더/타이머를 factory가 스스로 시작하지 않는다. base geometry와 pose 코드는 웹 및 오프라인에서 같은 import/commit을 사용한다.

실시간 adapter는 ScrollTrigger p, first-visit t, 감쇠한 pointer를 공통 pose 함수에 넘기고 renderer.render()를 1회 수행한다. Remotion adapter는 plain React canvas ref로 Three renderer를 만들고 useCurrentFrame()/fps에서 t를 계산한다. frame이 바뀔 때 evaluateIntroPose(frame/fps, viewportSpec)를 호출해 같은 scene을 직접 렌더한다. 텍스처/폰트/PMREM 준비와 해당 프레임 렌더가 완료되기 전에는 Remotion delayRender handle을 유지하고, GPU 완료 경계(오프라인 검증용 gl.finish 또는 동등 renderer sync)를 지난 뒤 continueRender한다. 실패는 명시 cancelRender/제작 로그로 처리한다. async texture 로드 중 캡처하거나 임의 timeout으로 성공 처리하지 않는다. 처음/중간/마지막 frame을 순서와 무관하게 재렌더하여 deterministic 여부를 비교한다.

파이프라인은 승인 후 (1) 공유 factory/pose의 웹 Hero 검증 (2) Remotion composition에 같은 canvas adapter 연결 (3) 정지 match frames PNG 출력 (4) Studio 실제 재생/프레임 이동 (5) 명시된 MP4 export (6) 웹 <video> preload/decode 및 live handoff 검사다. 브라우저 raw 검수 영상과 이 MP4는 별도다. 인트로에는 다른 영상 텍스처를 중첩하지 않는 기본안으로 구성해 seek/decode 비결정성·중복 렌더를 피한다. intro의 원화/geometry/광원은 모두 공유 자산이다. HyperFrames 자산은 story/preview/live mesh material 역할이며 이 공유 intro의 조형을 대체하지 않는다.

색 관리: 동일 Three renderer version, outputColorSpace=SRGBColorSpace, ACESFilmic tone mapping, exposure 동일값, canvas alpha 설정/배경 합성도 동일하게 고정한다. 입력 color texture sRGB, normal/roughness linear. browser HDR/OS wide-gamut 변수를 제어하고 QA는 SDR/sRGB baseline으로 한다. Remotion PNG는 같은 renderer 출력에서 얻고 MP4 H.264 yuv420p BT.709 태그로 export한다. 웹 decoded video의 BT.709 변환이 live sRGB와 미세 차이를 낼 수 있어 PNG match와 decoded MP4 match를 따로 검사한다. 태그가 같다는 이유로 seam 합격 처리하지 않는다. 검정/중간회색/피부/금속 highlight patch와 얼굴 윤곽 crop을 직접 비교한다. 필요한 경우 encode/canvas 색 보정을 명시하고 재렌더한다.

viewport spec은 CSS width/height, device scale, renderer pixel ratio, output width/height, crop/safe-zone, FOV/framing id를 구분한다. 기본 QA 1920×1080·DPR1·renderScale1에서 PNG/live 픽셀 비교를 먼저 고정한다. 배포 DPR1.5 adaptive profile은 같은 CSS composition/framing을 사용하고 물리 픽셀 밀도만 바꾼다. 1440×900(16:10)을 1920×1080(16:9) 영상 cover로 억지 crop하지 않는다. 1920×1080, 1440×900, 390×844 별도 framing spec/export를 기본으로 준비하고, 중간 aspect에는 letterbox/crop safe-zone 일치 또는 live intro를 선택한다. 서로 다른 프레이밍의 영상→live 전환을 감추기 위한 fade는 금지한다.

frame95→live H2(p=0)의 scene/camera/material/object pose는 수학적으로 동일하다. 영상 마지막 frame이 실제 decoded 상태이고 live world도 ready일 때 DOM video의 visibility ownership을 같은 animation tick에서 넘긴다. 마지막 1frame hold는 허용하되 사용자에게 장시간 대기시키지 않는다. 첫방문에서 웹 scene 자산이 아직 준비되지 않았는데 video만 먼저 끝나면 portrait/DOM/CTA를 즉시 유지하고 오류/지연을 기록하며 live가 ready되면 동일 안정 pose로 수렴한다. 이 경우 seam 미검증/개선 대상으로 남긴다.

Skip·scroll-interrupt·revisit의 기본은 공유 live entry다. skip을 누르면 video 재생/decoder를 멈추고 현재 live pose→H2 안정으로 짧게 수렴한다. 사용자 scroll은 같은 pose evaluator에서 scroll p를 최종 소유하며 intro가 p를 덮어쓰지 않는다. 영상 autoplay/네트워크/render 실패 시에도 같은 공유 scene의 실시간 first-visit sequence를 실행해 접힘/광원/원화 등장 경험을 유지한다. 원화/DOM만 있는 fallback은 WebGL 자체 불능의 기능 복구 경로다. Remotion 렌더 실패를 live fallback으로 숨겨 ‘Remotion 사용 완료’라고 보고하지 않는다. G1 통과 제출에는 composition source + 실제 export + 웹 연결 위치 + decoded playback/handoff 증거가 모두 필요하다.

19.4 제공된 Lusion 원본 URL의 접근 결과 — 실제 시청 범위 0초
