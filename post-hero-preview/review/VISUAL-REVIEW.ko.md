## 검수 증거

`scripts/capture-stage-review.mjs`는 하나의 화면당 1600×1000 PNG를 저장한다. 분할·콜라주가 아니다. `output/playwright/stage-review/` 아래 순서대로:

1. `01-distance-ko.png`
2. `02-play-ko.png`
3. `03-opened-letter-ko.png`
4. `04-read-dom-ko.png`
5. `05-read-dom-es.png`
6. `06-ending-es.png`

`stage-review.json`의 stage/floorColor/lightSignature/cameraZ는 실제 scene mesh/light 값을 읽는다. 색과 카메라 값이 다르다는 것은 보조 증거이며 심미적 완성 판정이 아니다. 이전 ZIP에서 추출한 `baseline-*-1440x900.png`는 원래 `fcf726a` 캡처이고 현재와 뷰포트가 다르므로 픽셀 비교로 해석하지 않는다.

이번 빌드 TypeScript/Vite 통과, 상태 단위테스트 4/4 통과. 큰 화면 검수 35/35 통과, JavaScript 예외 0. 독립 보고서 `stage-review.json`을 기준으로 한다. 모바일 390×844 KO/es-DO 각각 4구간, 총 8개 케이스의 가로 넘침·장면 분리와 엔딩 제목 대비를 별도 재검수했다(두 언어 제목/페이지 바탕 대비 약 9.52:1)(`mobile-polish-report.json`). 이전 `review/qa-report.json`의 51개는 **fcf726a 시점의 기준 결과**이며 이번 수정 후 전부 재수행했다고 주장하지 않는다. 캡처 런너의 소프트웨어 WebGL은 느려 실제 개봉 상태 도달까지 기다린다. 실제 기기 60fps·Safari·통합 Hero 접속 품질의 증거가 아니다.

## 인수 시 유지할 계약

같은 Scene 인스턴스의 바닥·봉투·컷아웃을 유지하며 progress와 opening만 부모가 공급한다. 단계별 새 배경 이미지로 치환하지 않는다. reduced-motion의 4개 정적 pose는 유지한다. 엔딩만 재생성하거나 승인 컷아웃을 다시 그리지 않는다.

최신 7종 말, 커플 조커와 귀족, 기존 7개 MP4 및 Remotion/HyperFrames 원본은 메인 환경의 승인 소스를 연결해야 한다. 로컬의 오래된 말/조커를 대체품으로 쓰지 않는다. Hero의 마지막 프레임→이 Scene 첫 프레임의 camera/object/light 계약은 전체 통합에서 확인해야 한다. 서버 공동 4계열은 명세만 있으며 이 로컬 프리뷰는 새 auth/RLS/채팅 전송을 만들지 않는다.

Library 업로드는 자동 승인 검토가 외부 목적지로의 비공개 소스/자산 업로드에 명시 사용자 승인이 없다는 이유로 거절했다. 승인 대기 중이며 다른 경로로 우회하지 않았다.
