# Marble 이벤트·경제 독립 QA

검증 날짜: 2026-10-11 UTC. 새 화면/도시 자산 제작과 별도로 엔진, 공개 이벤트, 표시 타임라인, 파산 확인을 검토했다. 게임의 경제 밸런스나 상용 출시 적합성을 입증하는 플레이테스트는 아니다.

## 확인 결과

- 새 방은 `economicVersion: 2`로 시작한다. 건설비는 도시 구매가의 40%/60%/80%를 10 단위로 반올림하며 최소 40이다. 액션 노출, 서버 검증, 실제 차감, 다음 건설비 표시, 최종 자산 평가가 같은 `marbleBuildCost`를 사용한다.
- 저장된 `economicVersion: 1` 및 버전 미지정 방의 건설비는 단계당 100을 유지한다. 기존 18칸/40칸 판별은 `boardVersion`을 따른다. 이 변경은 저장방을 새 가격표로 강제 재평가하지 않는다.
- 24개 도시 × 3단계 × 경제 버전 미지정/1/2의 **216개 건설 전이**를 임시 assert 스크립트로 확인했다. 정확한 비용을 가진 경우 승인, 비용보다 1 부족하면 거절, 건설 후 현금 차감/단계 증가/자산 보존/원본 상태 불변을 검사했다.
- 부족한 의무 지급은 현금을 일부 먼저 차감하지 않고 `pendingPayment`로 남는다. 위기 이벤트에는 지급할 금액과 계정 방향이 있으나 완료된 `moneyDelta`는 없다. 화면도 이를 `미지급 · 해결 필요`로 표시하고 가짜 음수 차감을 만들지 않는다.
- 은행/공동 기금/상대 플레이어의 **3개 채권자 경로**에서 대출 300, 채무 330, 의무 지급 1회, 지정된 차례/단계 복귀, 재대출 거절을 확인했다. 실제 임대료 위기 및 카드의 상대 부담금 경로는 기존 엔진 테스트에서도 검사한다.
- 파산은 지급 완료로 표현되지 않는다. 파산 후 현금은 그대로이고 미지급 항목은 종료 결과로 정리된다. 실제 브라우저에서 `파산 선택 검토`와 `돌아가기`는 액션을 보내지 않았고 최종 확인만 `declare-bankruptcy` 1회를 보냈다.

## 계정·금액·카드 의미

`pay`, `crisis`, `bonus`, `loan`, `repay`, `buy`, `build`의 계정과 금액을 검토했다. 공동 기금 납부/수령은 은행으로 잘못 표시하지 않는다. 독점 경고에서 카드를 뽑은 사람과 실제 부담금 대상이 다를 때 지급자는 대상 플레이어이며, 카드 공개 → 부담금 산정 → 실제 지급 또는 미지급 위기를 구분한다.

검토 중 열차 운임과 독점 부담금 산정 이벤트의 계정 필드 누락을 발견했다. 엔진 소유자가 `fromAccount`/`toAccount`를 추가했고 기존 열차/경고 테스트에 이를 검사하는 assert를 보강했다. 산정 이벤트에는 `moneyDelta`가 없고 실제 지급 이벤트에만 차감이 있다.

무료 열차에도 출발/도착 칸은 표시한다. 계정 필드가 있어도 차감이 0이면 `현금 변동 없음`으로 표시하고 은행 지급 화살표나 지급 완료 문구를 만들지 않는다. 브라우저에서 이 동작을 다시 확인했다. 카드 아이콘은 보상/비용/무인도/열차 계열을 구분하며 설명 문구를 유지한다.

## 표시·음향 검증

같은 사건의 카드가 React DOM에 반영된 후 해당 cue를 예약한다. 네 사건을 약 640ms 간격으로 표시했고 해당 카드 제목과 음향 노드 예약 시점의 제목이 일치했다. 최신 Chromium 계측에서 표시→첫 oscillator 예약 차이는 약 **0.2–1.7ms**였다. 이는 로컬 합성 이벤트의 예약 계측이며 스피커에서 실제 소리가 시작되는 시간이나 네트워크 지연 측정이 아니다.

최초 스냅샷/좌석 변경에서는 과거 cue를 재생하지 않았다. 동작 감소에서는 여러 사건을 최신 사건으로 즉시 압축했다. 새 사건 추가는 표시 중인 사건을 재시작하지 않는다. 결과가 오면 일반 사건 대기 타이머를 취소하고 결과음은 GameFeedback이 담당한다. 단계의 `win` cue는 이중 재생하지 않는다. 타이머 정리·결과 우선·재접속/좌석 변경·동작 감소는 전용 단위 테스트가 검사한다.

## 실행 근거와 한계

실행한 저장소 검사:

```sh
npm test -- --run src/games/marble.test.ts src/app/MarbleBoard.test.tsx src/app/MarbleEventStage.test.tsx src/app/marble-presentation.test.ts
```

위 검사에서 46개 테스트가 통과했다. 계정 필드 보강 후 엔진/단계 테스트 31개를 다시 실행해 통과했다. 추가 경제 matrix는 `/tmp/marble-economic-qa.ts`, 실제 합성 이벤트와 확인 버튼 브라우저 검사는 `/tmp/check-marble-stage.mjs`로 실행했다. 이 임시 도구는 저장소의 새 운영 기능이 아니다.

실기 음향 청취, 모바일 사용자 제스처/탭 숨김 복귀, 실제 Supabase 두 세션 경기, 장시간 승률/턴수/경제 균형은 이번 독립 QA에서 검증하지 않았다. 새 가격표가 도시 간 투자 차이를 줄이는 방향인지 판단하려면 별도 플레이테스트가 필요하며, 여기서는 계산과 상태 전이의 일관성만 확인했다. 진행 중인 디자인 작업의 최종 화면/자산 품질 판정 및 전체 빌드·전체 테스트는 루트 검증 결과를 따른다.
