# 세 게임 구현·실사용 재검수

2026-10-11. 대상은 도미노·자이푸르·스플렌더다. 다른 다섯 게임은 통합 회귀 검사 대상이며 상업 품질 평가를 새로 수행하지 않았다.

Method: dual-agent (A: sol_domino / sol_jaipur / sol_splendor · B: luna_domino / luna_jaipur / luna_splendor)

Impeccable `critique`·`audit`, Ponytail Audit/Review와 설치된 GameDev의 game-feel·feedback-recipes·game-ui-ux를 적용했다. 게임마다 A는 디자인/조작을, B는 공식 detector와 별도 브라우저를 독립 검사했다. 세 A 평가가 끝난 뒤에만 root가 B 결과를 읽었다. 한 검사 배치와 한 수정·확인 배치 뒤, 스플렌더 높이와 자이푸르 모바일 버튼의 실패 assertion만 좁혀 수정·재확인했다. 넓은 디자인 검수를 다시 시작하지 않았다.

## 판정

핵심 규칙·조작·그림 안내는 구현돼 있다. 기존 문서의 ‘UI 미구현’ 상태는 오래된 기록이었으며 바로잡았다. 다만 계획의 모든 세부 항목과 상업 출시 검증이 완료된 것은 아니다. 로컬 데모와 엔진/SQL fixture에서 사용 가능 범위를 확인했으며 실제 인터넷 운영 서비스의 출시 승인은 별도로 남는다.

## 기계 검출과 디자인 판단

게임별 CLI detector는 모두 `[]`(0개)이었다. root 공통 PlayApp/GameFeedback 검사도0개다. 실제 브라우저 공식 detector 주입은 도미노22·자이푸르32·스플렌더62 annotations였으며 같은 방 shell 항목이 중복된다. 이를 독립 제품 결함116개로 합산하지 않는다. 게임판 안의 카드/더미 계층, 의도된 사암색/아이보리, 초대 코드 자간은 맥락상 오탐이다. 일부 작은 보조 글자와 대비는 실제 개선 대상으로 확인했다. overlay가 문서 폭을 늘린 측정은 제품 overflow에서 제외했다. 주입은 headless에서 확인했으며 사용자에게 실시간 보이는 브라우저 overlay는 제공하지 않았다. 임시 detector 서버는 종료했다.

제품에 맞는 테이블·상품·보석 재질은 유지할 가치가 있다. 같은 실제 물체로 미리보기·확정·도움말을 연결하고 비공개 보너스와 예약 얼굴을 지킨 점도 강점이다. 큰 디자인 교체보다 입력 맥락·복합 상태·복구 안내를 보강하는 것이 필요한 수정이었다.

초보자는 보너스·팀/낙타·영구 할인 예외를 상세 규칙에서 확인해야 한다. 키보드 사용자는 선택 이후 맥락 복귀를 특히 필요로 한다. 작은 화면 사용자는 판매와 정산 영역의 이동 비용에 민감하다. 판매6종·시장12장은 게임의 선택지이며, 동시에 여러 행동을 확정하도록 요구하지 않고 하나의 행동 트레이로 결정 부담을 줄인다.

## 같은 날의 실제 플레이 후속 수정

위 점수·373개 테스트와 검수는 이전 단계의 기록이다. 이후 도미노 → 자이푸르 → 스플렌더 순으로 두 독립 한국어/도미니카 스페인어 플레이 화면을 전달하고, 별도 방에서 실제 두 사람 UI로 경기 진행을 검수했다. 발견한 재경기·결과 문구·모바일 판매 위치·공지 만료/겹침·상품 점수/보너스 기준·선택 전 카드 비용·상태별 보석 안내·예약 카드 구매 및 단계 표시 문제를 수정했다. 기존 게임의 원격 변경도 통합했다.

후속 전체 검사에서는 48파일433개 테스트와 TypeScript/Vite/Edge 빌드가 통과했다. 마지막 도미노 설정 동기화 한 줄 수정은 관련16개 테스트와 빌드를 추가로 통과했다. 사진과 실제 경기·통제된 컴포넌트 검사 근거는 [후속 수정 보고서](reviews/LIVE-PLAY-FIXES-2026-10-11.md), [독립 두 사람 검수](reviews/LIVE-TWO-PLAYER-QA-2026-10-11.md), [사진 목록](screenshots/live-play-2026-10-11/README.md)에 구분해서 기록했다. 기존 상업 출시 관문의 완료를 뜻하지 않는다.

도미노 AI는 game-ai 스킬을 적용해 쉬움/보통의 기본 판단도 보강하고, 어려움에 공개 패스·남은 패 수·팀 관계와 제한된 가상 경기 탐색을 추가했다. 별도의2001–2200 시드에서 좌석/팀을 바꾼400판씩의 대전에서 어려움은 보통보다 두 팀전 모드 각각60.51%·64.72%의 결정 승률을 보였다. 실제 상대 손패나 엔진 난수는 판단 입력으로 쓰지 않는다. 1대1은 두 사람 모드로 유지되며 봇 기능을 새로 추가하지 않았다. [AI 구현·비교 근거](reviews/DOMINO-AI-UPGRADE-2026-10-11.md)와 [독립 검수](reviews/DOMINO-AI-INDEPENDENT-2026-10-11.md)를 참고한다.

재현 스크립트·검수 문서·런타임 자산/출처 원본은 보존하고 검사 중 만든 임시 프로필·로그·캡처는 정리한다. 게임별 A/B 문서의 ignored `output/`·`/tmp` 경로는 검사 당시 산출물 위치이며 정리 뒤 제공되는 영구 파일 링크가 아니다. 원격 push는 사용자가 추가로 명시했으며 정상 main 업데이트로 수행한다. 공개 배포/클라우드 설정 게시 완료를 뜻하지 않는다.

작업 임시 경로140개(프로필/캡처 디렉터리 포함)를 정리했다. 실행 중 개발/SQL fixture의 로그, 설치 의존성·빌드와 원본 생성 아트는 보존했다. Impeccable snapshot은 세 게임 중 최저29/40을 보수적으로 기록한 첫 평가이며 비교 추세는 아직 없다. 영구 기록은 이 문서이며 `.impeccable` 캐시는 Git 대상이 아니다.

남은 디자인 우선 항목은 P2 자이푸르 모바일 손패↔판매 트레이 이동이다(`/impeccable adapt`: 장기 개선 시 선택한 패 근처에 행동 트레이 배치). 선택형 P3 도미노 드래그도 아직 없다. 다음 확인은 실제 두 기기 환경에서 정상 경기·연결 실패를 검증하는 일이다.
