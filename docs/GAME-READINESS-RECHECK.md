# 세 게임 구현·실사용 재검수

2026-10-11. 대상은 도미노·자이푸르·스플렌더다. 다른 다섯 게임은 통합 회귀 검사 대상이며 상업 품질 평가를 새로 수행하지 않았다.

Method: dual-agent (A: sol_domino / sol_jaipur / sol_splendor · B: luna_domino / luna_jaipur / luna_splendor)

Impeccable `critique`·`audit`, Ponytail Audit/Review와 설치된 GameDev의 game-feel·feedback-recipes·game-ui-ux를 적용했다. 게임마다 A는 디자인/조작을, B는 공식 detector와 별도 브라우저를 독립 검사했다. 세 A 평가가 끝난 뒤에만 root가 B 결과를 읽었다. 한 검사 배치에서 찾은 문제를 한 수정 배치로 처리하고 수정 부분을 한 확인 배치로 제한했다.

## 판정

핵심 규칙·조작·그림 안내는 구현돼 있다. 기존 문서의 ‘UI 미구현’ 상태는 오래된 기록이었으며 바로잡았다. 다만 계획의 모든 세부 항목과 상업 출시 검증이 완료된 것은 아니다. 로컬 데모와 엔진/SQL fixture에서 사용 가능 범위를 확인했으며 실제 인터넷 운영 서비스의 출시 승인은 별도로 남는다.

## 기계 검출과 디자인 판단

게임별 CLI detector는 모두 `[]`(0개)이었다. root 공통 PlayApp/GameFeedback 검사도0개다. 실제 브라우저 공식 detector 주입은 도미노22·자이푸르32·스플렌더62 annotations였으며 같은 방 shell 항목이 중복된다. 이를 독립 제품 결함116개로 합산하지 않는다. 게임판 안의 카드/더미 계층, 의도된 사암색/아이보리, 초대 코드 자간은 맥락상 오탐이다. 일부 작은 보조 글자와 대비는 실제 개선 대상으로 확인했다. overlay가 문서 폭을 늘린 측정은 제품 overflow에서 제외했다. 주입은 headless에서 확인했으며 사용자에게 실시간 보이는 브라우저 overlay는 제공하지 않았다. 임시 detector 서버는 종료했다.

제품에 맞는 테이블·상품·보석 재질은 유지할 가치가 있다. 같은 실제 물체로 미리보기·확정·도움말을 연결하고 비공개 보너스와 예약 얼굴을 지킨 점도 강점이다. 큰 디자인 교체보다 입력 맥락·복합 상태·복구 안내를 보강하는 것이 필요한 수정이었다.

초보자는 보너스·팀/낙타·영구 할인 예외를 상세 규칙에서 확인해야 한다. 키보드 사용자는 선택 이후 맥락 복귀를 특히 필요로 한다. 작은 화면 사용자는 판매와 정산 영역의 이동 비용에 민감하다. 판매6종·시장12장은 게임의 선택지이며, 동시에 여러 행동을 확정하도록 요구하지 않고 하나의 행동 트레이로 결정 부담을 줄인다.

## 새 측정 근거

운영 preview의 게임3×언어2×선택8 =48회. 클릭 capture부터 선택 `aria-pressed` DOM 변경까지 최대16.4ms, 관측 구간 longtask≥50ms는0개였다. 다음 rAF callback은 물리 화면 표시/paint 완료 시간이 아니다. 실제 인터넷·물리 기기·전체 경기의 응답 지연값으로 사용하지 않는다.

로컬 PGlite SQL/RLS fixture의 두 독립 Chromium context에서 세 게임 각각6개 행동·버전8 일치·방 종료 뒤 view 제거·해당 private 필드 계약을 다시 통과했다. Realtime이 없는 fixture이며 매 단계 명시적 snapshot 조회를 사용했다.

## 남은 출시 관문

1. 실제 Supabase URL/공개 키와 배포 서비스에서 두 기기 전체 경기·Realtime·지연/끊김/응답 유실/재접속 검증.
2. 물리 모바일·키보드/스크린리더·스피커/이어폰 청취와 실제 초보자 이해도·전체 경기 성능 검증.
3. 보존한 출판사 아트와 게임 명칭의 상업 사용 조건 확인.

검수 통과는 이 관문들의 완료를 뜻하지 않는다. 기존 도미노/스플렌더 모바일 진입 제한, 여덟 게임, 엔진/비공개 view/free-tier 보호는 유지한다. 클라우드 설정 초안은 게시되지 않았으며 환경 설정의 저장·게시 여부는 별도다.

## 최종 확인 및 정리

수정 후 게임별 확인, 원격 민화투 변경 통합, 전체 테스트/운영 빌드와 GitHub 푸시 결과는 이 절에 최종 기록한다. 재현 스크립트·검수 문서·런타임 자산/출처 원본은 보존하고 검사 중 만든 임시 프로필·로그·캡처는 정리한다. 게임별 A/B 문서의 ignored `output/`·`/tmp` 경로는 검사 당시 산출물 위치이며 정리 뒤 제공되는 영구 파일 링크가 아니다.
