UV를 다시 입력으로 누적 변형하던 별도 결함도 immutable 좌표로 정정했다. 작은 면+실제 return의 고립 구도는 성립했지만 전체 출발 경로 완료는 아니다.

## 중단 프로세스와 다음 검수 게이트

1. **현재 scope 동결:** 이번 감사자가 코드/자산/브라우저를 바꾸지 않는다. Hero 소스는 새 Sol High에게만, 후반은 별도 Sol의 계획 작업에만 맡긴다. `LandingWorldHost` 같은 공유 경계에 동시 수정이 필요하면 먼저 파일 소유자와 변경 경계를 합의한다.
2. **모순 없는 최신 brief 하나를 기준으로 삼기:** B 정적 구도·기존 사용자 자산·보호 카피/8개 route·섹션 분리·데스크톱 우선·모바일 최후순위를 한 장의 요구사항표로 고정한다. 오래된 A 추천, Gate0 승인 대기, Impeccable Product/Design의 현행성 주장을 새 지시보다 앞세우지 않는다.
3. **정적 방과 이동 Hero를 별도 검수:** B 정적 구도는 이미 승인된 기준이므로 다시 콘셉트 승인을 요구하지 않는다. 새 구현의 실제 desktop 렌더가 승인된 B의 크기/점유/주인공 배치를 따르는지 먼저 대조한다. 그 뒤에만 Hero 이동의 입장·중간·도착·역행을 검수한다. 계획서 숫자·world 좌표는 후보 설명이며 제품 UX 계약이 아니다. 불합격이면 원인 측정 전 다음 시각 patch를 덧대지 않는다.
4. **후반은 별도 계획/페이지 검토:** 기존 story, gallery, letter, ending을 기능/원문 보존 경계에 맞춰 따로 설계한다. 피드백은 독립 `/feedback`, 편지는 독립 `#papi-letter`, 게임은 실제 `/play?game=` 목적지로 남긴다. 후반 계획이 승인되기 전 Hero와 합쳐 새 runtime/콘텐츠를 만들지 않는다.
5. **증거를 분리해 제출:** 각 범위별 실제 browser 원본 캡처/영상, 화면 크기, 언어, route, 입력/역행, 검수자 판정과 미확인을 기록한다. B 수동 검출 결과로 보고된 `src/landing` 13개와 `post-hero-preview` markup 7개 검사에서 finding 0, warning 0은 그 범위의 정적 검사 결과다. 경고 0도 시각 승인/실제 브라우저 pass가 아니다. 빌드/test·정적 코드·기술 profile·렌더된 mockup은 각각 해당 범위로만 표기한다. 불합격 1건은 다음 변경의 시작점이지 평균점수로 상쇄할 항목이 아니다.
6. **스킬 사용을 증명:** 사용 시점/읽은 SKILL 경로·버전, 특정 디자인/동작 결정에 적용한 문장, 결과 source, 실제 검수 artifact를 연결한다. Impeccable critique와 technical audit를 실행했다면 출력 파일을 남기고, motion은 `review-animations`, 성능은 계측 결과로 분리한다. 스킬 언급만 있는 기존 계획을 실행 기록으로 바꾸지 않는다.
7. **합격 전 확장 금지:** 새로운 아트 변형, asset generation, 페이지/기능 확장, 모바일 마감은 desktop scope의 독립 시각 승인 뒤 진행한다. 인증 공동 기능은 backend 검사와 분리해 실제 두 사용자의 두 기기 검수 뒤에만 사용 가능으로 표시한다. main 병합/배포는 별도 사용자 승인이 필요하다.

또한 1440에서 발견한 상단 가로선을 별도 분리 검수했다. canvas-only에도 남아 DOM 장식이 아니었으며 원화/확장 행을 읽는 셰이더의 조건부 좌표가 mip derivative를 오염시킨 것이었다. 연속 좌표로 모두 읽은 뒤 outside 영역을 선택하도록 고쳤고 실제 PNG에서 선 해소를 확인했다. 이는 승인 원본 내부 픽셀을 다시 그리는 수정이 아니다. 문서의 이 국소 정지 개선과 최신 전체 입력/시각 완료는 구분하며, v9 최종 검사는 별도 기록한다.

### 최신 v9 기술 검수와 모션 판정의 구분

관련27검사·production build, 두 해상도의 pointer/정착 후 반전·resize 복귀는 통과했다. 원시 로그와 실제 GPU 버퍼 기반 상태 보고는 `runtime-hybrid-v9-validation/`에 있고 최초 가시 프레임도 entrance0·자산/warmup 준비 뒤 표시됨을 확인했다. root는 proof-v4의 두 해상도 실제 중간/B를 다시 열어 가로선·세로 국가 HUD 해소를 확인했다. 영상 파일의 실제 길이는 ffprobe 기준8.40초이며1배속이다.

독립 검수는 실제 MP4 .2초 간격 추출 시퀀스와 정지 자료를 확인했지만 연속 실시간 재생은 하지 않았다. 결론은 중간 구도 기반 확보와 별개로 인물 투명 퇴장/배경 교체/전경 퇴장이 공간 이동보다 강하고, 역방향에서 두 풍경 겹침이 두드러진다는 것이다. 총괄은 이를 완료로 바꾸지 않고 같은 담당자에게 자산·구도·카메라를 유지하는 output-only 시간 관계 후보를 비교하도록 지시했다. 실패 횟수에 따른 교체, 새로운 장식/광원/카메라 재설계, 전체 source 갈아엎기는 하지 않는다. 상세 개선 지시는 HERO brief에 있다.

### 시간 관계만 고치라는 지시도 충분하지 않았다

output-only timing A는 운동을 먼저 배치했으나 실제 p=.1875에서 여전히 큰 우주 풍경과 B 얼굴이 겹쳤다. 이 후보는 미통합이다. root의 카메라/기하 고정 제한은 이 단계의 구조적 해결을 막는 가정이었다. 독립 소스 검토도 매 progress camera eye 기반의 near 재배치와 camera matrix 기반 Hero 재투영이 독립적 시차를 상당 부분 상쇄하며, 카메라는 .10에 멈추고 실제 배경 교체는 .14–.16의 전체 alpha로 일어난다고 확인했다. approach/표면 변형 자체가 없다는 뜻은 아니다.

다음 지시는 시각적 p0/B endpoint만 보호하고 중간의 기존 좌표/카메라 추종을 전제로 삼지 않는 실제 공간 구도 두 안이다. 두 풍경을 각각 opaque로 유지하고 world-anchored 구조·카메라·depth/frustum 관계로 중간 화면을 만든다. 특정 옆 열기/힌지/복도는 해법으로 지정하지 않는다. 실제 중간 정지 비교 후 모션을 만든다는 원래 사용자 요구로 돌아간다. 모델/담당자 교체나 장식 추가가 아닌 총괄 지시·구조 가정의 정정이다.

### 실제 두 공간 연구: 기술 대리목표로는 구도가 해결되지 않았다

같은 담당자의 output-only `world-anchored-study-v11`은 늦은 표본을 중간으로 잡아 B 확대 화면만 보였다. root는 이를 공간 연결의 증거로 인정하지 않았다. v12는 실제 공유 경계를 캡처했다. root와 독립 Sol 검수자가 A-early/A-crossing/B-crossing을 직접 열었다. 초기에는 거대한 토끼/침대 조각과 다른 배율의 우주 커플이 붙어 있고, 경계에서는 B의 세로 이미지 끝이 우주 옆에 드러난다. 독립 판정도 **평면 이미지를 옆에서 접근 가능한 방으로 간주한 설계 전제**를 문제로 지적했다. 두 안 모두 제품에 통합하지 않았다.

깊이 순서에서도 C는 radius80의 외곽 원경이고 B는 그 안쪽의 가까운 방이다. 이 배치에서 먼 C가 가까운 B를 물리적으로 가릴 수 없다. 이미지 끝을 기존 source column에 맞추거나 alpha를 제거하는 것만으로 초기 비노출→최종 도착의 공간 관계가 해결되지 않는다. 초기 꼭짓점 중 near plane 뒤에 있는 점의 단순 projected bounds를 화면 점유율처럼 사용하는 검수도 배제했다.

총괄의 보완 지시는 ‘모든 world matrix를 불변으로 하라’가 아니다. **카메라 추종으로 시차를 상쇄하지 않되 의미 있는 표면의 실제 이동/변형을 허용**한다. 두 장소가 어떻게 실제로 가려지고 드러나는지를 설계하고, raw artwork 경계를 출입구로 대신하지 않는다. 담당자는 종료된 두 배치의 근거를 보존하고, 장식/조명이 아닌 구조 대안 한 개와 최소 검증 구도를 먼저 제안한다. 현재 제품은 push된 v9 `50a98c2…`로 보존한다. 이번 판정은 정지 연구와 해당 source에 한정하며 새 연속 모션·후반·모바일 검수는 아니다.

### 바닥/턱 대안도 테두리로만 읽혔다

동일 담당자가 제안한 바닥 아래/뒤 B 배치의 최소 연구 `threshold-study-v13`을 root도 실제 열었다. 초기 방 누출이 사라지고 B 도착이 유지돼도, 중간의 좁은 상단 C와 가로 trim 같은 턱은 공간 통과로 읽히지 않았다. 왼쪽의 직접 C/B 경계도 남았다. 한 번의 정지 연구로 종료했고 제품 통합·조명/장식 보강·긴 녹화를 하지 않았다. 이 결과를 ‘안 가림/깊이 존재/오류0’의 기술 성공으로 뒤집지 않는다.

중간 인물 배율0.95–1.05는 담당자가 제안한 실험 목표이며 사용자의 고정 계약이 아니었다. 총괄은 사용자의 ‘갑작스러운 크기 변화 금지’와 경로 전체의 배율 고정을 구분하도록 정정했다. 실제 연결 공간이 아니라 원화 둘레의 얇은 경계만으로 문제를 해결하려는 가정이 반복됐다. 다음에는 재사용할 원화와 별도로, 출발 공간·실제 가림 구조·목적 공간의 관계를 함께 설계해야 한다. 이 관찰은 해당 세 PNG/연구 source에 한정되며 실제 rich Hero 첫 방문·1440/모바일·연속 모션은 이번에 확인하지 않았다.
