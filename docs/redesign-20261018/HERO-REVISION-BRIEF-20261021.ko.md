# Hero 공간 전환 — 현재 작업 지시

상태 갱신: 2026-10-21. 이 브리프는 현재 공간 연구와 다음 검토 조건을 지정한다. 화면·모션·전체 랜딩의 합격 선언이 아니다. 상세한 이전 설계와 실패 증거는 [3b901a0 시점의 같은 문서 원문](https://github.com/da960822-ux/gitactions-main/blob/3b901a099f28a46dfa122ea9c85023010d8d2551/docs/redesign-20261018/HERO-REVISION-BRIEF-20261021.ko.md)에 보존돼 있다.

## 현재 상태와 판정

- 이 브리프의 제품 점검 기준은 `a1004ed`; Hero 공간 비교의 제품 기준은 `5c12f9b`다.

- 새 Hero 연구는 제품에 통합되지 않았다.

- 현재 연구 산출물은 `output/current-review/hero-spatial-rework-20261021/hero-wall-volume-current/`에 있다.

- 현재 유효한 연구 checkpoint의 source SHA-256은 `e28adc595dba724565d5c6718464b62c472d20193a07571e992052a8c8bf6f84`다. 보고서와 각 artifact hash를 대조해 root가 직접 확인한 실제 표본은 `.12`, `.35`, `.44`다. 같은 연구 폴더는 갱신되므로 이후 결과는 source/hash가 일치하는 범위에서만 읽는다.

- 이전 캡처·후보·카메라 키는 현재 결과나 지시가 아니다.

- `.12`에서는 I 원본 끝과 검정 여백은 사라졌고 남성은 읽힌다. 여성은 오른쪽 frustum 밖으로 자연스럽게 일부 잘리며 I/C 퍼즐 seam은 남는다.

- `.35`에서는 70% 인쇄판 접사가 사라졌지만 왼쪽에 약 440px의 실제 회색 면과 얇은 전면이 남는다. B는 약 40px의 토끼/사진 strip, 그 오른쪽에는 raw B/C edge이며 인물은 읽히지 않는다.

- `.44`에서는 실제 회색 면이 약 1340px를 차지해 남성 전체와 여성 얼굴 일부를 가린다. 첫 B 인계로는 불합격이다.

- 이전 `2c19fa51`의 `.50`/`1`에서 좋아 보였던 단일 벽 인계는 이번 소스의 결과가 아니다. 그 표본을 새 checkpoint의 합격 근거로 재사용하지 않는다.

- p0의 원본 대비 평균 차이는 `0.026757/255`, 최대는 `97`이다. 이는 거의 정합된 결과이지 bit-exact 보존 주장이 아니다.

- 따라서 현재 연구는 실패/보류다. 얼굴 보존 개선, 카메라 경로 수학, 경계 분류 또는 테스트 통과를 시각 완료로 대체하지 않는다.

- 이 세 장은 정지 2.5D 연구다. eye-inside 실내 복원, 연속 모션, 1440 독립 검수, 모바일, 실GPU 성능을 입증하지 않는다.

## 현재 연구 형상과 다음 원인 조사

현재 연구에는 관측된 I 석벽 edge의 depth `4→5.8` 구간을 잇는 하나의 불투명한 안쪽 벽이 구현돼 있다. 그 물리적 끝 뒤에서 빈 mouth가 시작된다. 이 연구 벽은 새로 저작한 진단용 면이며 원본에서 복원한 실내 재질이나 제품 통합 형상이 아니다.

`.35`/.44의 실제 결과는 B 인계가 여전히 불합격임을 보여준다. 현재 report의 101 pose × 63 raw-edge 샘플은 미소유 edge를 찾지 못했지만, 유한 표본이므로 픽셀/미술 통과를 뜻하지 않는다.

승인 B는 **최종 원화 프레이밍과 원본 인물 정체성**을 뜻하며 world pose를 고정하지 않는다. B world pose/distance120/yaw60, `.50` 이후 camera 고정은 root가 추가한 구현 제약이었고 사용자 요구가 아니므로 철회한다.

현재 owner는 유지한다. owner, 추가 Sol 자문(`/root/sol_spatial_architecture_consult`), 독립 감독이 **L자 얕은 실내 한 안**에 합의했고 root는 기존 renderer에서 이 안을 구현해 첫 bounded actual을 수행하도록 허가했다. 이는 미검증 구현 가설이며 시각 합격이나 owner 교체가 아니다.

경로는 같은 I 석재 jamb 뒤 끝을 먼저 지난 뒤 왼쪽의 새 얕은 실내로 이동해 가까운 rigid B를 발견하고 승인된 B 최종 프레이밍을 회수한다. 실제 측벽·발밑 바닥·desk 하부가 주변 공간을 책임져야 하며, 원본 B 하단을 floor로 취급하지 않는다. B world pose/end eye/배율은 함께 조정할 수 있지만 원본 B/P를 분해하지 않는다.

우선 일반 depth 관계를 사용한다. 기존 finite-B 12-hull 분류를 필수 계승하지 않으며, portal이 필요하면 실제 실내 구조를 분류한다. I/C의 기존 consistent far handoff를 검토할 수 있지만 handoff만으로 fade를 공간 전환 완료라 부르지 않는다. 새 asset·light·장식은 만들지 않고 필요한 기존 재질만 최소 적용한다. atlas 재질과 추가 gaze-only 수정은 보류한다.

다음 조건은 구조 후보를 검토할 때 함께 지킨다.

- 승인된 I와 B의 원본, B 도착 시 프레이밍과 인물을 보호한다.

- 승인 B의 인물·헤드셋·침대·토끼·사진의 정체성·원본 RGB를 새로 생성하거나 바꾸지 않는다. 같은 픽셀의 기하 분리와 원근 변화까지 금지하는 조건은 아니다.

- 구현은 합의한 이 한 안으로 제한한다. 새 renderer나 대안 구조를 추가하지 않는다.

- 보호 원본의 부족한 뒷면을 사실처럼 꾸며내지 않는다.

- 특정 힌지, 복도, 회전 방향이나 카메라 이동량을 미리 정답으로 고정하지 않는다.

제품 카메라와 공통 Host/연결은 root 소유다.

현재 Hero visual/motion/asset owner는 Sol이며, Luna는 명확한 기능 요구와 인벤토리를 맡는다.

실패 횟수에 따른 담당자 교체는 하지 않는다. owner에게 실제 프레임·측정과 잘못된 전제 또는 빠진 제약을 전달하고 같은 owner가 수정한다.

## 검수 순서와 완료 기준

1. 첫 bounded batch는 1920×1080에서 같은 source로 최대 다섯 actual still을 잡는다: p0, P가 마지막으로 읽히는 상태, B의 첫 부분 노출, 두 얼굴이 처음 읽히는 상태, B 도착. 각 PNG의 source/artifact hash와 DPR·렌더 환경을 기록한다.

2. 이 정지 표본을 독립 검토한 뒤에만 다음 단계를 진행한다. 승인 I/B, 원본 인물, 접합·가림, 실제 실내의 공간 책임을 확인한다. B만 보이는 도착 프레임은 전환 증거가 아니다.

3. 정지 구도가 성립한 뒤 1440×900에서 실제 native scroll로 정방향·역방향·중간 반전·직접 도착을 확인한다. 모바일은 데스크톱 검수 뒤 마지막이다.

4. 구도·공간·목적·craft 각 검토 점수는 4/5 이상이고 blocking 문제가 없어야 한다. 테스트·TypeScript·build는 시각 판단을 대신하지 않는다. SwiftShader는 실제 GPU 성능을 증명하지 않는다. 이전 실패 기록은 보존한다.

## 보호 범위와 작업 역할

Hero 작업은 다음 기능과 콘텐츠를 변경하지 않는다.

- 승인 I/B/P 원본, 첫 화면 카피와 언어 전환
- 여덟 게임, 게임 route, 갤러리 자산·팔레트·배치
- 편지 주소·제목·원문 5문단·서명
- L01–L16 발견 행동과 R01–R04 공동 기능
- API, 인증, 양측 동의, 권한, RLS와 free-tier 보호

게임/후반/갤러리 owner가 소유한 연결 계약을 보존한다. 독립 toy table/list를 기본 흐름에 넣지 않는다.

기존 Ponytail full, Impeccable craft-floor/critique, GPT Taste, Emil Animate, Three.js scene/camera 지침을 범위에 맞게 적용한다.

실제 화면·입력·접근성 증거를 디자인 검토와 연결하고, 누락된 자료를 확인한 것처럼 쓰지 않는다.

새 renderer, 라이브러리, 자산, 장식·광원으로 구조 문제를 가리지 않는다.

새 자산·조명·장식은 만들지 않는다. 기존 재질은 필요한 범위만 최소 적용하며 구조나 가림 문제를 가리는 데 쓰지 않는다.
