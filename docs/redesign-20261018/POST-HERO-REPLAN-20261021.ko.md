**자산 경로 정정:** 아래 이전 F6 표의 `yeonseok-lisbeth-cutout.webp`는 반실사 셀카 파생본이며 경로가 계획에 있다는 사실만으로 최신 승인 자산이 되지 않는다. root가 두 원본을 직접 열어 비교했고, 실제 F6는 기존 `approved-couple-room/approved-character-reference.png`와 opacity mask를 유지하도록 지정했다. Hero/B와 같은 승인 인물·화풍을 보존하며 새 얼굴이나 가짜 셀카 기억을 추가하지 않는다.

### 독립 평가와 수정 기준

디자인 검수 A(Sol)와 detector/실제 브라우저 근거 B(Luna)는 구현자와 분리한다. A가 평가를 마치기 전 detector 결과를 A 또는 총괄의 평가 종합에 섞지 않는다. Impeccable Nielsen 점수는 원래의0–4/해당 최대점으로 보고한다. 별도의 사용자 목표 점수는 **5점 만점**으로 Hero/후반 각각 구도·톤의 일관성·공간/모션·가독성·맥락에 맞는 상호작용을 평가하며, 각 영역4점 이상과 중대 P0/P1 없음이 목표다. 점수 목표에 맞춰 실제 점수를 올려 쓰지 않는다.

실패하면 같은 담당자에게 관찰 프레임/입력→문제의 원인→잘못된 프롬프트 전제→개선 지시를 전달한다. 한 구현 묶음을 한 번에 검수하고 수정 묶음 뒤 확인해 무한 미세 패치를 피한다. 단위검사 통과/새 자산 수/코드량은 시각 합격이 아니다. 데스크톱1920→1440을 먼저 완성하고 모바일390은 마지막에 확인한다. 실제 GPU 성능과 SwiftShader 결과는 구분한다.

이 문서 담당자의 산출물은 콘텐츠·구도 재계획이다. Hero 실제 수정과 병행해 후반 내용을 구체적으로 계획하라는 현재 지시를 따른다. 문서 담당자가 후반 구현까지 수행했다는 뜻은 아니다. 이후 사용자는 불필요 코드/자산 삭제와 리팩터링도 지시했고 별도 담당들이 수행 중이다. 공유 소스·카메라·UI·자산·원문은 이 문서 작성 과정에서 수정하지 않았다. 과거 Gate 0의 승인 대기 문구를 현재 작업의 중단 사유로 사용하지 않는다. 구현·검수·승인의 상태는 계속 따로 기록한다.

**최종 인수 정정:** 병행한 Hero 실제 수정 시도는 총괄 검수에서 거절됐고, 총괄이 보존 patch를 기준으로 해당 5개 파일의 변경 hunk를 되돌렸다. 최초 화면/B 정지 프레임의 픽셀 안정성은 확인됐지만 Hero 품질 통과는 아니다. 해당 시도 p=.18에는 여성 crop, p=.20–.24에는 떠 있는 평평한 방과 빈 틈이 남았다. 아래 F0 보존 요구와 F1–F6 계획은 이 실패를 해결한 구현 결과가 아니다.

**최신 상태:** aperture A 실패 뒤 같은 담당자가 승인 B에서 역설계했고, 현재 파생 전경/국소 alpha와 연속 RGB 연결을 적용한 실제 런타임 v9를 검수 중이다. root는 두 해상도의 실제 중간 PNG에서 방 점유·얼굴 보존과 원경 접합/옛 소품 잔상 개선을 확인했다. v9 중간 프레임의 근경 연결·잔류 원경·샘플 경계·HUD는 개선했고 기술 검사도 통과했다. 독립 모션 검수에서는 fade/배경 교체가 지배적이었고 시간 후보 A도 중간 풍경 겹침을 해결하지 못했다. 현재는 승인 endpoint를 보존한 output-only world-anchored 공간 두 안을 검토하며, 전체 모션·후반 통합 통과가 아니다. 상세 진행은 `HERO-REVISION-BRIEF-20261021.ko.md`를 따른다. 후반의 공유 카메라·연결부는 확정하지 않는다. embedded 엔딩의 잘못된 처음으로 링크는 `#home`으로 수정했다. 아래 콘텐츠 대본은 여전히 계획이며 구현 완료가 아니다. 데스크톱 우선·모바일 마지막 순서를 유지한다.

## 0. 앞선 계획에서 부족했던 내용과 이번 보완

앞선 계획은 여덟 역할과 기술·검수 조건을 길게 적었지만 **실제로 어떤 내용을 어떤 순서로 보게 할지**를 충분히 쓰지 않았다. 원래 DESIGN/EASTER-EGGS가 기대하게 한 개봉의 물성, 직접 남긴 흔적, 승인 사진의 발견, 두 사람이 함께 원인이 되는 공동 놀이가 결과에서는 작은 버튼과 별도 판에 머물렀다. 아래는 그 격차에 대한 자체 재검토다. 정식 독립 critique 실행이나 이미 해결한 제품 상태를 뜻하지 않는다.

| 빠졌던 기준 | 앞선 계획의 약점 | 이번 문서에서 구체화한 내용 |
|---|---|---|
| 장면마다 새로운 실제 콘텐츠 | ‘스토리/테이블/편지’라는 역할과 safe-zone만으로는 볼거리와 머물 이유가 만들어지지 않음 | §1.1의 화면 등장 순서·직접 입력·물리 결과·다음 장면 단서, KO/es-DO 초안 |

따라서 목표는 페이지를 세 템플릿으로 줄이거나 20개를 강제로 보여주는 것이 아니다. 기본 흐름의 실제 내용과 행동을 풍부하게 하고, 이미 있는 기능을 보조 panel 대신 해당 물체의 의미 있는 결과로 돌려놓는 것이다.

## 1. 이번에 고정할 방향

이 집의 주인은 한국의 Yeonseok과 도미니카의 Lisbeth다. 함께 통화하며 여덟 게임을 하려고 만든 사적인 공간이다. 첫 방문에는 만든 이유를 느끼고, 다시 오면 바로 게임을 고르고, 편지를 읽고 싶으면 언제든 읽을 수 있어야 한다.

후반의 기본 스크롤 순서는 **승인 B 방 도착 → 거리와 제작 동기 → 놀이 테이블과 기존 게임 갤러리 → 같은 책상의 봉투 발견·개봉 → 편지 읽기 → 같은 공간을 돌아보는 엔딩**으로 정한다. Hero의 `#games`와 `#papi-letter`는 이 순서를 건너뛰는 직접 경로다. 이야기를 끝까지 보거나 장난을 풀어야 게임·편지를 여는 구조는 쓰지 않는다.

**게임 목록 뒤의 기본 화면은 세 가지뿐이다: 봉투 발견·열기 → 원래 편지 읽기 → 짧은 엔딩.** 게임 설명·번역 소개·아이디어 소개·장난 실험실·공동 세션 안내를 이 사이의 독립 스크롤 장면으로 넣지 않는다. 현재의 긴 설명 구간은 ‘기능 보존’을 설명 장면 보존으로 잘못 확장한 결과이며 이 재계획의 기준으로 채택하지 않는다. 이 사이트의 목적은 둘이 실제로 놀고 편지를 읽는 것이다. 섹션을 빠르게 지나가게 줄이기만 하는 대신, 게임 선택 이후의 행동과 감정 흐름을 바로 연결한다. 길이는 실제 이야기·독서·행동이 필요한 만큼 정하고 임의 vh/필수 시청 시간으로 맞추지 않는다.

**이것은 전체 페이지를 세 섹션으로 끝내자는 뜻이 아니다.** 전체는 아래 여덟 역할을 가진다. 게임 뒤 세 역할을 선명하게 하면서도, 그 앞에는 공간 도착·확인된 제작 동기·실제로 만져 보는 놀이 맥락과 완전한 여덟 게임 선택이 있어야 한다. ‘너무 짧고 내용이 부족하다’는 문제는 빈 화면의 스크롤 길이나 설명 문장 수를 늘려 해결하지 않는다. 각 장면에서 새로 보는 내용·직접 할 수 있는 행동·다음 장면을 이해할 이유가 달라야 한다.

| 7. 원래 편지·4+4 / F5 | 원문 5문단·주소·제목·서명, 양옆 네 송이씩과 선택 힌트 | 자기 속도로 읽고 장미 의미를 보거나 접음 | 원래 글 전체와 4월 4일의 의미. 중앙 독서 구도·자연 높이·움직임 정지. 자동 다음 장면/문단 요약 없음 |
| 8. 짧은 엔딩 / F6 | 같은 소품과 열린 편지를 돌아보는 구도, 온전한 두 사람, 선택한 장식 | 선택 게임으로 가거나 자기 장식을 두고 머무름, 필요하면 아이디어 페이지 이동 | 처음의 초대가 실제 ‘이제 같이 놀자’로 닫힘. 넓게 돌아보는 구도와 끝 hold. 새 설명 목록을 다시 시작하지 않음 |

기존 승인 커플 사진은 L09 셔터를 직접 열었을 때 사진 자체가 보상으로 보이게 한다. 가짜 추억 설명이나 매 장면 재사용 배경으로 쓰지 않는다. 승인 승패 반응은 실제 게임의 실제 결과에서만 보여주는 콘텐츠로 보존하고, 랜딩에서 임의 승패·가상 플레이 기록을 만들지 않는다. 이런 실제 내용과 사용자가 남긴 세션 그림/선택 장식이 풍성함의 근거이며, 새 여행·청혼·추억을 창작해 내용을 채우지 않는다.

### 1.1 화면에 실제로 넣을 콘텐츠 대본

아래 새 KO/es-DO 문장은 제작 동기와 행동을 전달하는 **카피 초안**이다. Lisbeth의 실제 발언 기록·원어민 검수 결과라고 주장하지 않는다. Hero의 기존 문구와 편지 literal은 재작성하지 않는다. 장면 전환은 사용자 스크롤에 반응하고, 장면 안의 물체 반응은 명시 입력으로 일어난다. 아무 장난도 누르지 않아도 기본 화면의 내용은 온전히 보인다.

**1) Hero — 선물한 사람이 먼저 보인다.** 기존 어두운 우주와 승인 두 사람 원화, 기존 `Baby, / 이거 내가 만들었어!` 또는 `Baby, / ¡lo hice para ti!`를 유지한다. 첫 인상이 큰 구조물·기능 목록보다 두 사람에게 가게 한다. `같이 놀자`와 편지 직접 이동은 처음부터 있다. 추가 카피를 얹지 않는다. 움직임을 기다리지 않고 실제 목적지로 갈 수 있는 것이 첫 행동의 보상이다. Hero 실제 수정은 담당자의 현재 결과로 검수하며 이 대본으로 통과를 선언하지 않는다.

**2) B 게임방 — 둘이 게임하는 모습을 온전히 한 번 본다.** 승인 `approved-couple-gaming-room.png`를 정적 구도의 기준으로 쓴다. 모니터·두 자리·핑크토끼를 포함한 기존 그림의 관계를 보존한다. 화면 중간에 큰 설명판을 덮지 않고 잠깐 그대로 머물 수 있게 한다. 짧은 한 줄이 필요하면 KO “Baby, 여기서 같이 놀자.” / ES “Baby, juguemos aquí.”다. 사용자는 두 자리의 실제 그림을 보고 다음을 선택한다. 인물 머리만 잘라 다음 장면마다 재등장시키지 않는다. 그림 속 소품을 새 실제 3D 인터랙션이라고 부르지 않는다.

**3) 거리와 제작 이유 — 불편을 한 번 말하고, 만든 행동으로 답한다.** F1의 기본 화면에는 `한국 · Corea`와 `República Dominicana` 두 표찰, 그 사이의 좁은 간극, 다음 놀이 물체가 놓일 면의 일부가 함께 보인다. 첫 beat의 KO 초안은 “Baby, 도미니카에서는 한국 리듬게임에 접속이 안 됐잖아.” / ES “Baby, desde República Dominicana no podías entrar al juego de ritmo de Corea.”다. 다음 beat는 KO “그래서 멀리 있어도 우리 둘이 같이 놀 곳을 만들고 싶었어.” / ES “Por eso quería hacer un lugar para que juguemos juntos aunque estemos lejos.”다. 문장 하나씩 읽을 여유를 두고, 스크롤할 때 같은 실제 전환 면이 간극을 지나 다음 받침으로 펼쳐지는 안을 검증한다. ‘언어 장벽/번역 기능/초대 방식’ 세 설명 chapter를 이 뒤에 더 붙이지 않는다.

표찰 옆에는 L16의 종이 tab이 기본으로 보인다. 뒤집으면 `같이 놀자 / Vamos a jugar` 같은 확인된 초대말의 같은 뜻을 반대 언어로 본다. 접힘 틈에는 L03/L13의 손잡이·세 종이 모서리가 보이고, 선택하면 작은 방/길의 변형을 볼 수 있다. 이것은 이야기 속 작은 발견이며 편지·다음 장면의 잠금 장치가 아니다. 앞서 읽은 이유에 사용자가 직접 한 번 답하는 경험이 된다.

**4) 함께 놀 준비 — 세 물체를 실제로 만져 볼 수 있다.** F2의 기본 구도는 큰 빈 상판이 아니라 다음 세 내용의 근접 배치다. 왼쪽은 끝 숫자가 읽히는 짧은 도미노 줄, 가운데는 핑크토끼 받침과 작은 조명 손잡이, 오른쪽은 연필이 걸친 빈 종이다. 봉투는 뒤쪽에 작게 예고한다. 가까운 모서리·중경 세 물체·먼 봉투로 깊이를 만들고 각 물체가 충분히 크게 보이게 한다. 장면 copy는 KO “Baby, 하나 눌러봐. 이것도 같이 놀 수 있게 넣었어.” / ES “Baby, toca uno. También puse estas cositas para jugar.” 정도다. 번호/16개 tab/크림 설명판은 없다.

- **도미노의 첫 연쇄:** 현재 타일의 숫자/방향을 보여주고 끝을 맞추게 한다. 현재 공급 타일로 가능한 `1|2 → 2|3 → 3|4 → 4|5` 같은 짧은 줄을 구성한다. 첫 타일을 누르면 같은 타일들이 차례로 넘어지고 마지막 타일이 작은 서랍을 연다(L01). 서랍 안의 보석/clip이 실제 장식으로 나온다(L15). 짧은 반응이 필요하면 KO “맞췄네 haha” / ES “Encajó, haha.”만 쓴다. 문구가 서랍 동작을 대신하지 않는다. 맞추기를 건너뛰어 완성 모습을 볼 수 있고 장식은 독립 접근도 가능하다.
- **핑크토끼와 빛:** 조명 손잡이를 움직이면 같은 승인 토끼의 그림자가 뒤 종이 벽에서 길어지고 작아진다(L04). 받침의 얇은 레일을 누르면 앞뒤로 한 바퀴 돌아 같은 자리에 온다(L08). 다른 승인 말 6개는 물체를 선택했을 때 선택할 수 있다. 살리·술리는 둘이 있는 한 그림이다. 캐릭터 이미지 교체만 성공 보상으로 세지 않고 그림자/가림·원근의 차이를 보게 한다. 무문구 반응을 기본으로 둔다.
- **그림이 소품이 된다:** 빈 종이의 연필을 누르면 같은 자리에서 선/도형을 그린다(L06). 뒤집기를 누르면 그 종이가 책상 뒤의 작은 받침에 세워진다. 사용자가 만든 그림이 현재 세션의 공간에 남아 엔딩에서 다시 보이는 것이 보상이다. KO “Baby, 하나 그려봐.” / ES “Baby, dibuja algo.” 외의 자동 대사는 붙이지 않는다. 그림을 보내려면 별도 R03 동의를 거친다.

추가 물건은 ‘다른 물건 보기’만 눌러야 존재하는 숨은 목록으로 몰지 않는다. 도미노 서랍의 카드 손잡이에는 L09 사진 셔터가, 카드 뒤 접힌 받침에는 L10 귀족 pop-up이, 종이 귀퉁이에는 L12 넘김책이 **그림으로 알아볼 수 있는 단서**로 남는다. 직접 열면 승인 커플 사진/귀족/말이 실제 내용으로 드러난다. L02 받침 홈·L05 렌즈·L07 막대·L14 바람 손잡이는 해당 물체를 가까이 보는 상태에서 다음 놀이로 이어진다. 기본 세 물체의 시선 순서는 유지하고, 16개 모두를 동시에 실행하거나 먼저 배워야 하지는 않는다. 보조 접근 목록은 발견하지 못한 사용자에게 같은 물체를 열어 주는 등가 경로다.

**5) 여덟 게임 — 조각이 실제 플레이로 이어진다.** 기존 여덟 자산/캡션/선택지/크기/색/배치를 유지한다. 원래 `Mami, 뭐부터 해볼래? / Mami, ¿por cuál empezamos?`와 기존 소개문을 그대로 쓴다. Domino·Leonardo·Splendor 등 선택할 때 중앙 물체가 바뀌고 이름·설명·목적지가 일치한다. 같은 여덟 게임을 끝까지 골라볼 수 있는 완전한 콘텐츠다. Catchmind를 골랐을 때만 원래 양언어 정답/번역·원문/한도 설명을 필요한 크기로 보여준다. 다른 게임이나 별도 scroll chapter에서 번역을 다시 설명하지 않는다. 게임 실행은 기존 `/play?game=<id>`다. 갤러리 후에는 새 놀이 테이블·설명 기능판을 한 번 더 만들지 않는다.

**6) 봉투 — 앞서 뒤쪽에 있던 작은 물체가 이번에는 중심이 된다.** 봉투는 F2의 예고와 같은 실제 mesh/재질을 F4까지 유지한다. 갤러리의 게임 조각이 봉투로 변신했다고 꾸미지 않는다. 앞판/봉인/플랩이 모두 읽히는 접사에서 KO “Baby, 이번엔 이거 열어봐.” / ES “Baby, ahora abre esto.”를 제안한다. 열기와 즉시 읽기를 나란히 제공한다. 사용자가 열면 봉인이 분리되고 플랩이 뒤로 젖혀지며 안감·종이 edge가 드러난다. 종이가 앞판 가림을 지나 올라온 뒤 펼쳐져 읽는 종이로 정착한다. 매 단계의 실제 깊이 변화가 내용이며 단순 overlay 확대가 아니다.

밀랍 샘플 L11은 핵심 봉인 옆에 작은 별도 눌림 물체로 보인다. 누르면 복원되고 YL/작은 하트 압인을 선택할 수 있다. 핵심 개봉을 막지 않는다. R01 ‘같이 열기’는 이 봉투에서만 작은 선택으로 제공한다. 양측 tab 동의 이후 같은 개봉을 볼 수 있지만 상대 기다림 없이 혼자 읽는 길은 항상 있다. 공동 기능을 사용하지 않으면 기본 개봉/독서 흐름에 연결 안내 화면이 끼지 않는다.

**7) 원래 편지와 여덟 송이 — 읽을 분량을 온전히 둔다.** `home.ts`의 주소·제목·5문단·서명을 기존 KO/ES 그대로 보여준다. 새 감동 문구나 요약으로 바꾸지 않는다. 화면은 단일 DOM 종이, 뒤/아래의 열린 봉투 일부, 왼쪽 네 송이와 오른쪽 네 송이뿐으로 정돈한다. 실제 편지의 전체 분량과 자기 속도로 읽는 시간이 장면의 핵심이다. 다른 커플 컷아웃·뒤 3D 본문 종이를 중복으로 세우지 않는다. 장미를 누르면 KO “4송이, 그리고 4송이. 우리 시작한 날 ♡” / ES “Cuatro rosas y otras cuatro. El día que empezamos: 4 de abril ♡”의 기존 의미 힌트를 본다. 4+4 양쪽을 동시에 식별할 수 있어야 한다. 이 날짜를 새 출석·수집·장미 장면 수로 늘리지 않는다.

**8) 엔딩 — 방금 한 행동이 같은 공간에서 다시 보인다.** 읽기를 끝내고 아래로 이동하면 같은 봉투/편지에서 실제로 뒤로 물러나 책상 구도의 일부를 회수한다. 사용자가 L06을 했다면 자기 그림, L15를 골랐다면 그 선택 장식이 지정 위치에 남는다. 하지 않았다면 기본 도미노·clip만 있어도 완성된 구도다. 승인 컷아웃은 이 한 구도에서 온전하게 쓰되 열린 종이를 가리지 않는다. KO “자, 이제 같이 놀자, Baby.” / ES “Ahora sí, vamos a jugar, baby.”와 선택 게임 진입 하나, 보조 `/feedback` 링크로 끝낸다. 새 소개·공동 기능·수집 결과 화면을 시작하지 않는다. 짧은 끝말과 달리 공간의 실제 회수·직접 남긴 흔적이 내용을 닫는다.

이 대본의 공간 이동은 이름만 Lusion식으로 부르는 효과 목록이 아니다. **B 그림은 고정**, 그 앞/곁의 실제 전환 면은 F1의 두 표찰을 지지하는 면→접힌 간극→F2의 제한된 받침으로 변하고, 가까운 모서리는 먼 물체를 잠깐 가렸다 드러낸다. F2의 봉투/그림/장식은 F4–F6까지 동일 ID·재질·위치 계보를 갖는다. 카메라가 움직이는 동안 법선·가림·투영 크기·광원 방향이 실제로 일치하는지를 정지 proof와 중간 pose로 검증한다. B 그림의 책상과 실제 새 받침의 의미상 연결을 동일 mesh 증거로 세지 않는다. 연결이 성립하지 않으면 geometry/구도를 고치며, 독립 장면 crossfade나 물체 수 증가로 대체하지 않는다.

승인 B 정적 방과 어두운 우주 Hero는 보존한다. Leonardo 초상, 사용자 제공 Splendor 커버, 나머지 여섯 게임의 복원 자산, 어두운 갤러리의 중앙 대표 물체+주변 일곱 물체·2×4 선택 배치를 보존한다. 후반의 새 표현은 이 둘 사이와 편지·엔딩의 공간 관계를 해결한다. 갤러리의 크기·자산·색·구조·배치를 바꾸거나 확대하는 작업은 별도 사용자 지시 없이는 하지 않는다.

세계의 바깥은 계속 어둡게 두고, 방의 따뜻한 빛이 책상과 편지까지 이어진다. 버건디는 천·봉투 안감, 로즈골드는 얇은 단면과 작은 반사, 아이보리는 읽는 종이에 쓴다. 큰 크림색 UI 판을 후반 배경으로 쓰지 않는다. 꽃은 **편지 읽기 장면에만 왼쪽 네 송이·오른쪽 네 송이**다. 4+4는 4월 4일의 의미이며 다른 장면의 꽃 장식 확장 근거가 아니다.

## 2. 읽고 본 증거와 그 한계

## 3. 모션보다 먼저 제출할 정지 프레임

**제작 가능성부터 검증한다.** 승인 B 방은 고정된 일러스트레이션이며 실제 내부를 탐색할 수 있는 3D 방 mesh가 아니다. 그 그림 속 책상/벽 사이로 카메라를 이동할 수 있거나 방을 입체로 복원했다고 전제하지 않는다. 책상·책·봉투 모티프의 반복은 의미상의 연결이며 동일 3D 공간의 증거가 아니다. 그림의 rigid plane과 실제 전환 mesh/소품의 경계를 정지 프레임으로 명시하고, 서로 다른 관찰각의 실현 가능성을 실제 렌더로 확인한 뒤 경로를 정한다. 성립하지 않으면 bridge 형상·구도를 다시 설계한다.

F1–F6는 아직 구현되지 않은 구도 제안이다. 그림 속 방과 새 소품 공간의 소재·빛·프레이밍 handoff가 실제로 성립하는지를 먼저 시험한다. 다시 거대한 갈색 접힘/빈 상판을 만들고 소품 몇 개를 올리는 구조를 채택하지 않는다. 높은 품질의 2D props와 DOM을 사용할 수 있으며, 실제 3D는 공간 전환과 깊이·가림·물성이 필요한 실제 mesh 물체에 집중한다. 전신 커플을 매 구간에 반복하지 않는다. 원화 속 커플과 별도 컷아웃을 중복 노출하지 않는 프레임별 소유권도 확인한다.

아래 F0–F6의 화면 구도부터 1920×1080, 이어 1440×900에서 KO/ES로 만든다. 숫자는 **화면 설계 기준**이며 현재 구현 측정값이 아니다. 좌표를 먼저 고정해서 승인 B 방을 억지로 맞추지 않는다. 프레임마다 실제 투영된 화면과 얼굴·본문·입력의 안전 영역을 비교한다. 최종 프레임이 실패하면 그 사이의 애니메이션은 제작하지 않는다.

## 4. 정지 프레임 사이에서 무엇이 움직이는가

카메라·공유 표면·광원·기본 pose는 **Hero 담당 한 명**만 쓴다. 후반 담당은 다음 목적 프레임과 가림·입력 요구를 전달하고 소품 자식 rig와 DOM만 맡는다. 두 담당이 다른 카메라를 붙이거나 같은 transform을 덮어쓰지 않는다. 아래는 구현 계약이며 이번 문서에서 실행하지 않았다.

| 연결 | 실제 공간 변화 | 중간 프레임·역방향 검사 |
|---|---|---|
| F0→F1 | 승인 B 도착 hold 뒤에만 후반 이동 시작. rigid 그림 앞/곁에 있는 실제 mesh bridge와 국가 표찰로 프레이밍을 연결하는 안을 시험한다. 그림 속 방 내부로 이동하거나 그림의 책상이 실제로 이어진다고 주장하지 않는다 | 시작·중간·도착의 실제 프레임에서 art/mesh 경계·광원·소재 연결을 확인한 뒤 채택. B 방을 다시 작게 축소하는 도착 금지. 역스크롤은 정확한 B pose로 복귀 |
| F1→F2 | 실제 mesh bridge가 있는 부분에서만 전경 간극·법선·가림 변화와 camera 이동을 시험한다. 제한된 받침 영역과 물체가 다음 상태로 이어져야 한다. 큰 접힘/빈 상판을 먼저 확정하지 않는다 | 정지 proof에서 경로와 구조의 가능성을 확인한 뒤 움직임 제작. 목적 물체가 통과 전에 보임. 판 관통·늘어지는 커튼·갈색 터널·검은 틈·단순 확대는 불합격. 같은 경로 역평가 |

클릭·스크롤·직접 anchor의 상태는 단일 편지 controller가 소유한다. 마지막 명시 입력을 우선하고, 진행 중 반전은 현재 q에서 시작한다. 수동 접기 후 같은 독서 영역에 머물러도 자동 재개봉하지 않는다. `#papi-letter`, 즉시 읽기, reduced motion은 원문이 공개된 읽기 pose로 직접 간다. 문서 처음부터 원문은 단일 DOM에 존재하고, 숨김·focus·`aria-expanded`는 실제 공개 상태를 따른다.

본문·버튼은 정상 문서 흐름에 둔다. wheel/touch를 가로채지 않는다. 스크롤 길이를 늘려 장면이 풍성해졌다고 판단하지 않고, 읽기와 선택 hold를 실제 사용에 맞춰 정한다. 이번 계획에서 제작 일정·필수 시청 시간·전체 vh를 임의로 약속하지 않는다.

## 5. 로컬 16개를 ‘발견하는 물체’로 보존

EASTER-EGGS v3의 L01–L16을 모두 유지한다. 기본 랜딩에는 번호·전체 tab·성공률·잠금·수집 진행률을 노출하지 않는다. 물체를 선택하면 **해당 물체와 그 조작만** 가까이 보이고, 닫기/Escape/스크롤 이탈로 원래 자리로 돌아온다. 필요한 안내는 물체 곁의 짧은 DOM 컨트롤로 제공한다. hover만으로 숨기지 않고 이름 있는 button/keyboard 경로를 둔다.

로컬 16개는 기본 스크롤의 별도 장난 방·설명 장·조작 패널 구간이 아니다. 해당 물체에서 명시적으로 열 때만 임시 공개하고, 닫으면 원래 물체와 스크롤 자리로 돌아온다. 놀이를 열지 않은 상태에서 `#games` 다음에 장난 화면이 끼어들거나 페이지의 기본 순서가 늘어나지 않아야 한다.

직접 찾기 어려운 경우를 위해 선택형 ‘다른 작은 물건 보기’를 둔다. 펼쳤을 때만 종이·타일·빛·말의 네 묶음에서 고르게 하고, 한 묶음/놀이만 열린다. 이 경로는 실제 물체의 같은 상태를 열며 별도 16개 실험실 화면을 만들지 않는다. 발견을 못 해도 모든 장난에 도달할 수 있고 핵심 편지·게임은 항상 별도로 열린다.

### 5.1 원래 기대한 경험과 현재 버튼 사이의 격차

아래 ‘현재’는 기존 실제 contact sheet와 읽은 source가 보여 준 범위다. 모든 버튼이 오작동한다고 주장하는 표가 아니다. 핵심은 입력이 성공했다는 사실과 사용자가 실제로 보고 얻는 보상을 구분하는 것이다. 이 대표 사례 외 L01–L16은 위 전수표, R01–R04는 다음 절에 그대로 보존한다.

| 대표 요구 | 원래 기대 경험 | 현재 화면/소스에서 보이는 격차 | 계획된 공간 보상과 확인할 프레임 |
|---|---|---|---|
| L01→L15 | 내가 놓은 타일이 마지막 물체를 건드려 서랍이 열리고 장식이 나옴 | 크림 판 안의 놓기/넘기기/서랍 버튼과 바깥 소품이 분리돼 보임 | 같은 근접 구도에서 타일 접촉→연쇄→걸쇠→서랍→장식까지 원인/결과가 보임. 선택 장식은 F6의 지정 자리에서 회수 |

승인 말 7종, 커플 조커 2종, 귀족 2종과 기존 컷아웃을 재사용한다. `robot` ID는 핑크토끼다. 실제 source/runtime 경로·승인 mapping과 원본 비율을 대조한 뒤 배치한다. 옛 ‘－’ 조커·옛 귀족·새로 생성한 얼굴로 대체하지 않는다. 2D 승인 원본은 standee로 쓰고 진짜 입체 캐릭터를 새로 만들었다고 보고하지 않는다.

모든 이벤트는 단일 포인터·터치·키보드 대안을 갖는다. 낙서는 도형 버튼 등가, 기울임·회전은 단계 버튼 등가를 둔다. 한 번에 하나만 활성화하고 독서·게임 진입·언어 변경을 우선한다. 무음 기본, 효과 off와 reduced motion에서도 정적인 완성 결과·초기화·종료를 제공한다. 반복 자동 힌트·보상 알림·읽음 추적은 넣지 않는다. 저장은 기존 계약대로 장식/효과 취향 정도이며 낙서는 세션을 넘기지 않는다.

## 6. 원격 공동 4개는 두 사람이 선택할 때만

랜딩 열람·편지·게임 선택은 로그인 없이 그대로 가능하다. 공동 놀이를 명시 선택한 뒤에만 기존 인증·비공개 초대/session 흐름을 사용한다. 상단 전역 로그인 벽이나 ‘연결하세요’ 대형 패널을 감정 흐름에 끼워 넣지 않는다. 기존 권한·초대·멤버십·한도는 약화하지 않는다.

공동 4개도 기본 스크롤에 설명/연결 패널을 삽입하지 않는다. 해당 봉투·그림·장식·리듬 물체를 선택한 맥락 안에서 opt-in으로 열고 취소/닫기 시 원래 자리로 복귀한다. 공동 놀이를 사용하지 않으면 게임 목록→편지→엔딩의 기본 흐름이 그대로다.

| 요구 | 초대가 나타나는 맥락 | 공동일 때만 달라지는 실제 결과 |
|---|---|---|
| R01 | F4 봉투 열기 옆의 작은 ‘같이 열기’ 선택 | 두 사람 각각 ready/동의 후 같은 개봉 사건. 상대의 읽는 속도·카메라·언어는 제어하지 않음. 혼자 열기 항상 가능 |
| R02 | F2 장식 고른 뒤 ‘보내기’ 선택 | 목록의 장식 ID를 제안하고 상대가 받으면 같은 물체가 공유 통로로 이동. 파일/선물 전송이나 자동 수락 아님 |

## 9. 기술과 자산의 최소 완전 범위

기존 React/TypeScript·직접 Three·GSAP와 이미 있는 상태/helper를 쓴다. 새 renderer·엔진·카메라 controller·animation library를 추가하는 계획은 없다. 공용 host가 renderer/scene/camera/resize/dispose/RAF를 단독 소유하고, 소품은 child group, DOM은 의미 있는 버튼과 글을 소유한다. 이벤트가 `selectedGame`이나 게임 engine·점수에 쓰지 않는다.

Remotion은 같은 pose의 공간/개봉 review frame·film 제작, HyperFrames는 고정 문구/표찰·선택 프리뷰의 제한된 타이포 안무를 맡는다. 같은 transform을 두 도구가 쓰지 않는다. 둘 다 실제 활용 요구는 유지하되 기존 source/export를 우선 매핑하고 필요한 구간만 수정한다. 과거 문서의 ‘MP4 7개’와 자기검토의 ‘현재 9개·runtime 직접 두 경로’는 서로 다른 시점의 자료다. 구현 착수 시 현재 파일·source·연결·시작/끝 pose·재사용 구간을 확인한다. 이번에 새 영상을 만들거나 전부 적용됐다고 주장하지 않는다.

영상/live 연결은 같은 최종/첫 pose·crop·색 관리·광원으로 맞춘다. 본문·CTA는 영상에 굽지 않는다. 장면 전체를 다른 MP4로 crossfade해서 공간 이동을 대체하지 않는다. 실제 사용 source·export·웹 연결·브라우저 결과가 있어야 해당 제작 도구의 사용 완료로 기록한다.

신규 또는 수정 필요 자산은 먼저 실제 파일과 대조한다: 봉투 body/front/liner/flap/seal/insert와 hinge, 같은 표면의 접힘/테이블 pose, 각 장난 소품의 필요한 최소 rig, F5의 8송이 장미 배치, 읽기 종이의 무문자 재질. 이미 있는 자산을 다시 생성하지 않는다. 사진·얼굴·기존 갤러리는 보호한다. 새 환경/소품이 필요하면 provenance와 source/runtime mapping을 남긴다. 최종 프레임을 확인하기 전에 고비용 전체 영상을 렌더하지 않는다.

WebGL/context/decode 실패 시 게임·원문 DOM·기존 링크를 계속 제공한다. reduced motion은 접근성 경로로 같은 내용·행동·완성 상태를 제공한다. 오류 fallback 통과를 기본 시네마틱 품질 통과로 보고하지 않는다. 성능은 실제 renderer·GPU/SwiftShader·DPR·viewport·녹화 유무를 적고 측정한다. 소프트웨어 렌더링 결과를 사용자 GPU 결과로 바꾸지 않는다.

**알려진 fallback 회귀 — 기능 합격에 먼저 포함:** 총괄이 새로 수행한 B/1440 WebGL 명시 비활성 검수에서 Host tick의 `!world` 조기 return 때문에 `externalTick`/후반 progress가 갱신되지 않고 0에 머무는 문제가 확인됐다. 갤러리 `StudioScene`은 WebGL 실패를 잡지만 실패 상태로 전환하지 않아 `Preparando los juegos…`가 남는다. 반면 DOM 여덟 선택지와 직접 게임 링크는 존재하고 `Leer`로 원문 편지를 열 수 있었다. 따라서 ‘게임 진입 전체 차단’으로 표현하지 않는다. renderer 실패와 독립적으로 문서/후반 상태가 진행하고, 갤러리가 무한 준비 표시에서 명확한 실패/대체 상태로 끝나며, 여덟 선택·직접 링크·편지 읽기가 유지되는지 실제 WebGL 비활성 경로에서 확인해야 한다. 이 기능 회귀 해결은 시네마틱 완료 판정의 선행 조건이다. 이번 문서는 제품 소스를 수정하지 않는다.

### 9.2 불필요한 코드 정리의 계획 경계

사용자가 요청한 불필요 코드 정리는 기능/원문 삭제와 구분한다. 이 문서 작성자는 소스를 바꾸지 않으며, 총괄의 활성 배선/링크 감사 결과를 파일별 정리 목록의 근거로 쓴다. 가짜 ‘정리 완료’나 새 문서만 늘리는 결과로 대체하지 않는다.

- **기본 흐름에서 없어져야 할 UI:** 긴 invitation/translation/ideas 홍보 chapter, 16개 tab 실험실 wrapper, 본문과 별개인 중복 3D 본문 종이, 같은 커플 컷아웃 반복 노출. 기능은 각각 실제 게임 선택 맥락·물체별 입력·단일 DOM 원문으로 옮긴 다음 wrapper와 전용 dead CSS만 제거한다.
- **지워서는 안 되는 구현:** L01–L16 상태/helper·입력 검증·keyboard 등가, R01–R04 인증/동의·만료·RLS/free-tier, 편지 literal·단일 controller, 여덟 게임/선택/route, 승인 원본·provenance·기존 검수 증거. 보이는 panel을 없애며 이 로직까지 함께 삭제하지 않는다.
- **확인한 뒤 삭제할 코드:** 활성 host/route에서 도달하지 않는 preview/bootstrap·과거 버전 모듈, 옮긴 UI의 미사용 import/style, 중복 RAF/listener, 사용자 화면에 남은 독립 프리뷰/자산 미연결 안내 문자열. 현재 import·동적 import·script/test/fixture·asset 참조와 다른 담당 소유권을 대조한다. 이름이 옛 버전처럼 보인다는 이유만으로 파일을 일괄 삭제하지 않는다.
- **함께 고칠 연결:** 처음으로/되돌아가기의 실제 목적지, `#games`/`#papi-letter` 직접 착지·편지 공개, 선택 게임/언어/복귀, WebGL 비활성 시 tick/영구 준비 표시. 예를 들어 ‘처음으로’가 `#distance`에 연결된 경우 홈 첫 화면으로 가는 의미와 맞는지 감사 결과로 고친다. 감사 완료 전 현재 링크가 정상이라고 쓰지 않는다.

정리 결과는 삭제 파일 수보다 활성 구현의 단일 소유·참조 단절 없음·16+4/8게임/원문 보존으로 판단한다. scoped source diff와 실제 진입/복귀 검증으로 확인하고 광범위 reset·다른 담당 작업 제거는 하지 않는다.

다음 경우에는 해당 변경만 중단·복귀한다.

1. **원문/권한/게임 보호 위반:** 다른 소품 작업을 멈추고 원인을 고친다. literal·8개 route·게임/API·private/free-tier guard가 기준과 달라지면 시각이 좋아도 통합 보류다.
2. **갤러리 회귀:** baseline과 비교해 기존 자산·색·배치를 바꾼 후반 hunk만 되돌린다. Leonardo/Splendor를 포함한 기존 보호 자산은 유지한다. 전체 working tree reset은 하지 않는다.
3. **공유 공간 회귀:** F0 승인 B나 Hero 전환을 후반 연결이 망가뜨리면 그 연결 수정만 단독 소유자가 baseline으로 복귀한다. 독립 DOM·기능 작업은 보존하고 원인/목적 프레임을 다시 대조한다. 빈 공간을 꽃·조명·소품 수로 덮지 않는다.
4. **편지/독서 회귀:** 원문·장미·focus·즉시 읽기가 깨지면 마지막 안정된 편지 상태를 복구한다. 장미를 다른 장면에 더 배치하거나 본문을 줄여 맞추지 않는다.
5. **공동 실패:** 실패 round는 취소/회복 가능한 로컬 상태로 끝낸다. 미검수 공동 기능을 현재 가능으로 홍보하지 않고 해당 client/서버 연결만 분리해 고친다. 요구 R01–R04는 계획에서 삭제하지 않는다.
6. **시각 실패:** 담당자 자동 변경을 하지 않는다. 실제 프레임·측정·재현 경로로 실패 원인을 분석하고, 프롬프트의 잘못된 전제와 누락 기준을 고쳐 재설계·재검수한다. 기능 통과·새 URL·담당명 변경을 시각 통과로 쓰지 않는다. 같은 구조의 미세 패치만 반복하지 않는다.

롤백은 안전한 작업본/manifest와 파일별 hunk를 기준으로 한다. 다른 담당 변경을 덮거나 승인 원본·과거 증거를 지우지 않는다. main 병합·push·배포는 이번 계획에 포함하지 않는다.

이번에 하지 않은 것: 제품 구현·신규 자산 제작·영상 렌더/재녹화·전체 runtime/네트워크/실GPU/모바일 검수. 남은 핵심 위험은 Hero 소유자가 확정할 실제 도착 pose와 F1–F6의 연결, 원격 4개의 실제 두 사람 검증이다. 이 문서는 그 작업의 구도·순서·보호·합격 기준을 정의한 계획이다.
