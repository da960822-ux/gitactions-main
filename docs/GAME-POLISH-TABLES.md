# Table game polish: Jaipur, Splendor, Da Vinci

This pass is confined to the three `TableGames` views. It keeps each engine’s legal actions, public board, player hand, and result as the authority. No card, good, or tile values are added to the view; Da Vinci continues to render hidden opponent values as dots. Score motion uses `GameValue` and resets on the relevant player/game/round context.

| Game | Visual | UX | Public event feedback | Sound | Local interaction | Verification |
| --- | --- | --- | --- | --- | --- | --- |
| Jaipur | Retains the mapped Jaipur goods sprites and uses the shared room focus, spacing, score, and reduced-motion tokens. Round and token values use `GameValue`. | Exchange mode shows each selected count and keeps the exchange button disabled until the exact equal-count hand/market selection matches a server-provided legal action. Sale buttons keep the legal count and identify the face-up top token value; hidden lower tokens stay unshown. | Score deltas follow public token/round changes; sale labels distinguish the visible top token from a bonus tile whose value is only revealed on sale. Round wins and the current round stay visible. | No local cue. Central `runAction` audio should map confirmed `take` and `sell` transitions. | Trade selection stays local to the active view and clears when turn, round, market, or hand changes. | SSR component test checks top-token/bonus preview, confirms a deeper pile value is not rendered, and confirms score uses `GameValue`. |
| Splendor | Preserves mapped card/noble art; shared focus and reduced-motion rules apply. Public scores use `GameValue`; selection, bank, deficit, and return guidance stay text-readable. | The bank states the exact number of distinct colors required by the current bank. The token summary shows selected count, chosen return total, and hand total after the legal take. | Da Vinci | Keeps the ivory/obsidian number tiles and explicit black/white labels. Central `runAction` audio should map confirmed `draw`, `guess`, `skip-draw`, and `stop` outcomes, distinguishing public reveal from hidden-value data. | Target selection resets to a remaining hidden tile after a reveal. The view exposes no selection or action that can reveal a private opponent number. | SSR test gives an unrevealed tile a sentinel value and verifies it never appears; it also checks a guessed number without a legal matching action cannot enable submission. |

Card and result motion is a short opacity/vertical entrance on the real arriving node; there is no implied travel from a hidden deck. Jaipur preserves the identity key of existing market goods and marks a refill only when the public deck count/round shows a new draw; Splendor uses the public card ID so market replenishment and a newly reserved card mount once. The noble-choice panel emphasizes only when the server view offers a noble choice. Result banners carry explicit `win`, `lose`, or `draw` data for game-specific styling. Ambiguous Jaipur replacements that cannot be distinguished from public values stay static.

The component does not emit sound. Audio remains centralized so pending or rejected network actions cannot be presented as confirmed events. Reduced-motion users retain the same state changes and visible selections without decorative transitions.
