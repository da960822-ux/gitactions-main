# Splendor table polish

Splendor uses a game-specific table in `src/app/TableGames.tsx` and scoped styles in `src/styles/splendor-premium.css`. The rules, action payloads, and authority remain in the existing engine. The UI renders only the player view and the legal actions returned with it.

| Axis | Implemented behavior |
| --- | --- |
| Visual | A midnight teal table frames ivory panels and muted-gold accents. The desktop composition puts three available nobles in a horizontal top row, twelve development spaces in three market rows on the left, six round gem-bank controls in a right column, and the player’s token/bonus tray and reserved cards below. Each development face uses its individual image from `/images/splendor/cards/`; the stable 90-card mapping is `public/images/splendor/card-map.json`. Each noble and event image uses its mapped individual face from `/images/splendor/nobles/`. The source faces remain uncropped and their printed point/cost symbols are not covered by UI badges. Costs and bonuses stay available as readable DOM/accessibility text. |
| UX | The market keeps four face-up spaces for each tier. Card purchase/reserve controls are distinct, with exact remaining deficits on unbuyable cards; costs remain accessible without overprinting the source face. The bank presents each gem as a round, count-badged chip, with its label beside it; legal same-color-two actions and any return plan remain visible beside/below the same gem. The treasury counts gold once, exposes all six token piles and permanent bonuses, and shows three private reserved slots plus only the opponent’s reserved-card count. Multiple eligible nobles open an explicit legal-choice state. |
| Events and motion | Changes are derived from successive authoritative player views. First render does not invent events. Confirmed market arrivals, reservations, purchases, incoming tokens, noble visits, turn changes, and results get compact feedback in a fixed-height status slot shared with the turn guide, so an action does not shift the table. Incoming bank tokens travel to their matching treasury pile; newly gained bonuses and nobles receive a short highlight. A purchase shows the exact removed card folding into the portfolio only when one matching market or own-reserved card can be identified in the snapshots. Event state is keyed to the viewer and public turn counters. No action is animated as successful before its updated view arrives. |
| Sound | The shared sound controller owns all playback. Splendor cues follow confirmed token takes, reservations, purchases, noble choices, and authoritative public turn/result changes. This component adds no duplicate sound calls. |
| Additional interface | A public score strip tracks both players and marks whose turn it is. The 15-point final-turn notice uses public turn counts, including the pending-noble phase, to identify who actually has the last move. Reduced-motion mode removes motion and token-flight overlays; the controls remain keyboard-accessible with visible focus and 44px minimum targets. |
| Verification | `src/app/TableGames.test.tsx` verifies 90 unique card face paths, 10 unique noble face paths, exact engine-ID-to-image rendering, classic table regions and accessible bank actions, exact card deficit with gold wild tokens, capacity counting, opponent reserved-card privacy, initial-state event suppression, viewer isolation, purchase/token/noble/turn/result snapshot events, and pending-noble final-turn messaging. Browser verification is tracked separately in `output/playwright/game-polish/splendor-modern-browser.json` and `splendor-event-browser.json`. These use the local HTTP database fixture and an isolated engine-driven event fixture; they are not production Realtime verification. |

The distinct source card faces are kept at their original aspect ratio and keyed through the checked-in engine-ID map. The source images remain present in `public/images/splendor`; the modern table supplies layout, labels, and legal-action controls around them.
