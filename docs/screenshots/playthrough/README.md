# 한국어 / 도미니카 스페인어 실제 플레이 검수

각 게임을 한국어 p1과 스페인어 p2의 독립 Chromium 컨텍스트에서 새 초대방을 만들고 UI로 진행했다. 초기 배치를 임의로 설정한 fixture 스크린샷이 아니라 실제 사용자 행동으로 진행한 판의 중반 화면이다. 게임별 상세 범위와 오류는 아래에 순서대로 추가한다.

서버 환경: 로컬 PGlite HTTP 테스트 서버. 프로젝트의 SQL migrations/RLS와 빌드된 게임 authority를 사용하지만 실제 Supabase Auth/PostgREST/Realtime는 아니다. 상대 상태는 인증된 snapshot을 명시적으로 갱신했다. 실제 서비스의 실시간 푸시 전달·외부 번역 API·물리 오디오 검증을 뜻하지 않는다. 리듬 게임의 원작 내부는 한국어이며 외부 안내만 한국어/스페인어다.

## 1. 민화투

[한국어 중반](minhwatu-mid-ko.png) / [스페인어 중반](minhwatu-mid-es.png): 같은 방 version13, 각5턴 실제 진행, 손패 각5장, 바닥6장, 더미10장,75–50점. 양쪽 공개 상태 일치, 상대 손패/더미 비공개, 브라우저 page error0. 별도 QA방은20턴 완주와 양자 재경기 동의까지 통과했다. 두 후보 선택/세 장 전부 획득은 첫 QA경기에서 자연 발생하지 않아 해당 경기로 검증됐다고 주장하지 않는다. 실제 중반의 높은 획득 영역에서는 손패 조작에 세로 스크롤이 필요한지 추가 확인 중이다.

민화투 획득패 [한국어 근접](minhwatu-captures-ko.png) / [스페인어 근접](minhwatu-captures-es.png)은 별도의 새 경기에서6턴 실제 진행 후 본인 영역만 브라우저 캡처한 것이다(앞선75–50경기와 다른 판). 패 획득 전/이동 중/도착 후 목록을 추적해 빠진 패/잔류 placeholder가 없음을 확인했다. 전체 사진에서 작은 영역을 구분하기 어렵다는 피드백을 받아 근접사진을 추가했다. 독립 QA 실제 중반에서는1440×900에서 확정 버튼 하단919px/후반939px로 세로 스크롤이 필요해지는 P2 UX문제를 확인했고 수정 진행 중이다.
