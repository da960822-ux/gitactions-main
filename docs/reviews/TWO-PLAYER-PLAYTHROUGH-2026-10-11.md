# 두 플레이어 실제 UI 플레이 검수

한국어 p1과 도미니카 스페인어 p2는 서로 다른 Chromium 컨텍스트에서 초대방 생성·참여·양자 게임 동의를 거쳐 진행했다. 사진 담당과 독립 QA 담당은 별도 새 방에서 플레이했다. 경기 상태를 인위적으로 만들거나 action API로 입력하지 않고 실제 UI를 사용했다. 사용자에게 게임 하나마다 사진을 전달한 뒤 다음 게임으로 넘어간다.

기반은 기존 로컬 PGlite SQL/RLS/authority HTTP 서버다. 실제 Supabase Auth/PostgREST/Realtime 배포 검수는 아니다. 인증된 상대 snapshot을 테스트 코드에서 명시적으로 갱신했다. 외부 번역 서비스 및 물리 사운드는 별도 미검수다. 캡처 시 UI 애니메이션이 끝날 때까지 기다려 저장 상태와 표시 상태를 구분한다. 최초 러너의 잘못된 대기 조건/요청 직후 읽기 레이스는 수정 후 다시 실행했으며 제품 결함으로 세지 않는다.

## 민화투

- 사진 경기:10턴(각5), 손패5/5, 바닥6, 더미10, 점수75–50. 독립 QA는 실제20턴 완주, 승패 점수 일치, 재경기 동의와 새10장 손패까지 확인.
- 기본 그림 두 후보 선택은 별도 실제 경기에서 자연 발생했다. 세 후보 전부 획득/더미 두 후보는 해당 자연 경기에서 발생하지 않아 이번 경기로 검증했다고 주장하지 않는다.
- 매 턴 양쪽 공개 바닥·점수 일치. 상대 비공개 패 ID DOM노출 없음. 본인/상대 획득패의 DOM ID 집합은 public captures와 일치, 모든 SVG 로딩, 잔류 이동 복제본 없음. doubleclick은 한 번만 적용.
- P2:1440×900 중반부터 내 패 선택 후 확정/취소가 y885–919 또는905–939에 위치해 스크롤이 필요. 큰 고정 바닥높이와 양측 획득행 누적이 원인. 수정 진행 중.
- 사용자 캡처 피드백: 넓은 전체 사진에서38px 패와 작은 ‘내가 모은 패’ 구분이 약함. 실제 패 누락으로 재현되지는 않았지만 영역 식별성을 보강한다. 별도6턴 경기의 획득영역 근접사진도 제공.

사진은 [playthrough](../screenshots/playthrough/README.md)에서 게임별로 확인한다. 원시 재현 코드·로그는 `output/playwright/serious-play`와 `output/playwright/serious-qa`에 임시 보관한다.
