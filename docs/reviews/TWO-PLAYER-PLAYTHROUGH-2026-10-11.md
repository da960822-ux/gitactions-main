# 두 플레이어 실제 UI 플레이 검수

현재 작업 범위는 사용자 지시에 따라 **민화투만**이다. 아래 도미노·자이푸르는 범위 수정 이전에 수행한 기록이며, 추가 작업은 중단했다.

한국어 p1과 도미니카 스페인어 p2는 서로 다른 Chromium 컨텍스트에서 초대방 생성·참여·양자 게임 동의를 거쳐 진행했다. 사진 담당과 독립 QA 담당은 별도 새 방에서 플레이했다. 경기 상태를 인위적으로 만들거나 action API로 입력하지 않고 실제 UI를 사용했다.

기반은 기존 로컬 PGlite SQL/RLS/authority HTTP 서버다. 실제 Supabase Auth/PostgREST/Realtime 배포 검수는 아니다. 인증된 상대 snapshot을 테스트 코드에서 명시적으로 갱신했다. 외부 번역 서비스 및 물리 사운드는 별도 미검수다. 캡처 시 UI 애니메이션이 끝날 때까지 기다려 저장 상태와 표시 상태를 구분한다. 최초 러너의 잘못된 대기 조건/요청 직후 읽기 레이스는 수정 후 다시 실행했으며 제품 결함으로 세지 않는다.

## 민화투

- 사진 경기:10턴(각5), 손패5/5, 바닥6, 더미10, 점수75–50. 독립 QA는 실제20턴 완주, 승패 점수 일치, 재경기 동의와 새10장 손패까지 확인.
- 기본 그림 두 후보 선택은 별도 실제 경기에서 자연 발생했다. 세 후보 전부 획득/더미 두 후보는 해당 자연 경기에서 발생하지 않아 이번 경기로 검증했다고 주장하지 않는다.
- 매 턴 양쪽 공개 바닥·점수 일치. 상대 비공개 패 ID DOM노출 없음. 본인/상대 획득패의 DOM ID 집합은 public captures와 일치, 모든 SVG 로딩, 잔류 이동 복제본 없음. doubleclick은 한 번만 적용.
- P2 수정: 고정 바닥높이를 없애고 전체 폭으로 바닥패를 배치, 획득 영역 왼쪽에 본인/상대 표식을 배치, 확정/취소를 손패 옆에 배치했다. 원본48패·점수·매칭 규칙은 변경하지 않았다. 최종 새 경기20턴/11개 확인 통과, 오류0;1440×900에서 선택 버튼은 화면 안에 있었으며 마지막 취소 하단814px. 양쪽 획득 영역이 여러 줄로 쌓이는 조합에는 여전히 세로 스크롤이 필요할 수 있다.
- 최종 화면은 별도 새 경기10턴/version14,60–85점, 양쪽12장 획득·손패5장이다. 애니메이션과 점수 이동 종료/양측 버전 및 획득 DOM 일치 후 캡처했다. 경기 결과170–190 일치,22/26장 획득패 전면 표시, 재경기10장 초기화, 더블클릭 단일 적용 확인. 최종 CSS 네이티브84/84와 빌드 통과. 자연 경기에서는0/1/2손패 매칭 및 더미 두 후보가 발생했고3손패 매칭은 발생하지 않았다.
- 사용자 캡처 피드백: 넓은 전체 사진에서38px 패와 작은 ‘내가 모은 패’ 구분이 약함. 실제 패 누락으로 재현되지는 않았지만 영역 식별성을 보강한다. 별도6턴 경기의 획득영역 근접사진도 제공.

사진은 [playthrough](../screenshots/playthrough/README.md)에서 게임별로 확인한다. 원시 재현 코드·로그는 `output/playwright/serious-play`와 `output/playwright/serious-qa`에 임시 보관한다.

## 민화투 후속 UX 수정 — 최신 결과

앞의 수정 이후 사용자 요청으로 획득패의 겹침을 허용하고 피10장 행 규칙을 적용했다. root·솔·루나가 민화투만 수정/검수했다.

- 해결: 종류별 실제/도착예정 패를 합산해 열 너비 배분, 열끗/띠>5·피>10 겹침,피11/20/21/24장을10+1/10+10/10+10+1/10+10+4행으로 표시. 전체 원본 패ID 및 종류 수량 유지.
- 해결: 최근 획득의 지속 강조와 마우스/초점 원본SVG 확대. 넓은 화면에서 작은 패를 잃어버린 듯 보이는 문제를 줄이며 실제 누락을 주장하지 않는다.
- 해결: 손패 차례·금색 가능한 패, 키보드 초점 이동과Escape취소/복귀, 선택 후 버튼을 가까운 위치로 스크롤. KO 하단0.375px 초과 측정은4px scroll margin으로 보정. ES의 좁은 획득패에서 Mes11/12 글자가 다음 패에 가리던 월표시는 숫자로 간소화(접근성 설명 유지).
- 해결: 최근6개 중 genericturn이 유의미한 기록을 밀어내던 문제. 공개된 최근48이벤트 중turn을 제외한 기록과 실제 그림·점수 차이 제공. 서버 기록 보존 범위 내 표시이며 전체 경기 무제한 기록을 뜻하지 않는다.
- 경계 수정: 비어 있는 바닥의 이동 목적지 숨김 방지.
- 실제 최신1366×768 한국어/스페인어 20턴,13/13,오류0. 점수80–200/승자p2/획득26·22장 및 양측 상태 일치. 피14장은10+4, 모션 종료후 최근획득ID일치, 확대보기 원본로딩·Escape닫기·version불변, 화살표/선택취소초점복귀. 공개행동33개·52그림을 중반에 확인. 자연 빈바닥17–19턴 통과, 재경기10장 초기화.
- 미검수:운영 Supabase Realtime/물리 음향/현지화자사용자테스트. 이 자연 경기에는 손패3후보와 더미2후보가 발생하지 않았으므로 별도 네이티브 fixture 결과와 구분한다.

최종 강화 네이티브 검수140/140, 오류0. 같은 좌석·종류·같은 행에서만 의도적인 겹침을 허용하고 다른 종류/좌석/행의 충돌은 거부한다. 보존48카드 분포·피10/11/20/21/24의 정확한 행별 개수·끝패 로딩/잘림·빈바닥 비행·ghost 도착자리·숨김패 보안·모션축소·고도리·승패 및 재경기UI 확인. 별도 피행30개Room fixture도 전체ID/행/끝패/가로넘침 통과. 마지막 스크롤 보정 후KO1366 피21/24 버튼 하단764.375px,ES1440 피24는867.141px. 큰 게임판에서 세로 스크롤이 전혀 없다는 주장은 하지 않는다.

최종 월표시는KO/ES모두숫자이며,카드일러스트·꽃·종류·월·점수는확대보기/접근성설명에보존한다. 공용월태그 grid중앙정렬 때문에 마지막digit가가려지던경계는justify-items:start로보정했다. 마지막KO1366/ES1440피24 fixture에서 DOM Range로10/11/12의두자리모두노출폭안에있음을확인했다. 종료후빈손패와플레이힌트행은숨긴다. 최종관련20개테스트와빌드통과; 최신사진은 playthrough의minhwatu-pi24-{ko,es}.png이다.
